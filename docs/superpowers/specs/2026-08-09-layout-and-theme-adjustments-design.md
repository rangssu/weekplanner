# 레이아웃·테마 조정 4종 — 설계

작성일: 2026-08-09

## 1. 개요

지인(사용하는 스트리머)이 요청한 네 가지를 다룬다. 서로 독립적이지만 전부 **결과 이미지의 외형**을 건드리고, 두 개(2번·4번)가 같은 파일을 만지므로 한 설계에서 함께 본다.

| # | 요청 | 성격 |
|---|---|---|
| 2 | 달력 칸을 키워달라 | 레이아웃 재배치 |
| 3 | 다크 테마 선이 너무 옅다 | 테마 값 |
| 4 | 배경 이미지 위에서 달력 투명도 조절 | 새 기능 |
| 5 | 사이드바 박스 제목 수정 | 새 기능 |

## 2. 달력 세로 확대

### 2.1 요청의 실체

"칸 너비 증가"로 전달됐지만, 받은 참고 이미지를 캔버스 4000px 기준으로 환산해 재보니 **가로는 지금과 같고 세로가 커진 것**이었다.

| 항목 | 참고 이미지 | 현재 |
|---|---|---|
| 사이드바 폭 | ~895 | 900 |
| 달력 폭 | ~2862 | 2880 |
| 칸 가로 | ~409 | 410.6 |
| **칸 세로** | **~339** | **297** |

원인은 제목 줄이다. 지금은 제목이 캔버스 전체 폭을 가로지르고 달력이 그 아래 남은 높이만 쓴다. 참고 이미지에서는 제목이 사이드바 열 위에만 있고 달력이 캔버스 맨 위부터 시작한다.

```
지금                              바꾼 뒤
┌─────────────────────────┐      ┌────────┬────────────────┐
│ 8월              AUGUST │      │ 8월    │                │
├────────┬────────────────┤      ├────────┤   달력          │
│사이드바 │  달력           │      │사이드바 │  (세로 2070)   │
│        │  (세로 1878)    │      │        │                │
└────────┴────────────────┘      └────────┴────────────────┘
```

### 2.2 새 치수

```
CANVAS_CONTENT_HEIGHT = 2070   (2250 − 패딩 90×2)

왼쪽 열(폭 900)          오른쪽 열
  제목  160              달력  2070
  간격   32
  사이드바 1878
  ─────────
  합계  2070
```

- **사이드바 높이는 1878로 그대로다.** 지금 `BODY_HEIGHT`와 같은 값이라 사이드바 내부는 전혀 손대지 않는다.
- 달력만 1878 → 2070으로 커진다.
- `CELL_HEIGHT` = (2070 − 테두리 6 − 요일행 90) ÷ 6 = **329** (현재 297, +11%)
- `CELL_TEXT_HEIGHT` = 329 − 28 − 52 = **249** (현재 217)
- `CELL_WIDTH`는 410.57로 **변화 없음**

### 2.3 AUGUST 표기 제거

기능 자체를 없앤다. 제목이 900px 열에 갇히면 「8월」과 「AUGUST」를 나란히 둘 자리가 없고, 참고 이미지에도 없다.

- `HeaderConfig.showEnglishMonth` 제거
- `HeaderEditor`의 토글 제거
- `TitleBar`에서 영문 월 이름 렌더링 제거
- `MONTH_NAMES_EN`은 `calendar.ts`에 남기되 쓰는 곳이 없어지면 함께 제거

### 2.4 긴 제목 처리

**이 변경의 대가다.** 제목이 쓸 수 있는 폭이 사실상 캔버스 전체에서 900px로 줄어, 지금 기준으로는 긴 제목이 훨씬 일찍 잘린다.

`TITLE_KO_SIZE_STEPS`의 최소 크기는 지금 `TITLE_EN_SIZE + 8`(=104)이다. "영문 월 이름보다 작아지지 않는다"는 근거였는데, 영문 표기를 없애므로 그 근거가 사라진다. 최소를 **80**으로 낮춘다.

| 제목 길이 | 글자 크기 | 900px에 들어가는지 |
|---|---|---|
| ~6자 | 130 | 6자까지 |
| ~10자 | 112 | 8자까지 |
| 그 이상 | 80 | 11자까지, 넘으면 말줄임 |

11자를 넘는 제목은 말줄임표로 자른다. 크기를 더 줄이면 제목이 사이드바 본문 글자(54)와 비슷해져 위계가 무너진다.

### 2.5 상수 정리

지금 `BODY_HEIGHT`(1878)는 사이드바 높이이자 달력 높이다. 두 값이 갈라지므로 이름을 나눈다.

```ts
// 없앤다 — 이제 두 값이 다르다
export const BODY_HEIGHT = ...

// 대신 둘로 나눈다
export const SIDEBAR_HEIGHT = CANVAS_CONTENT_HEIGHT - TITLE_ROW_HEIGHT - TITLE_GAP  // 1878
export const GRID_AREA_HEIGHT = CANVAS_CONTENT_HEIGHT                                // 2070
```

`BODY_HEIGHT`를 남겨두면 어느 쪽을 뜻하는지 매번 헷갈린다. 이름이 값을 설명하지 못하게 된 순간이 바꿀 때다.

`Sidebar.tsx`가 박스 높이를 나눌 때 쓰는 비율(`GOALS_BOX_RATIO` 등)은 `SIDEBAR_HEIGHT`에 곱한다. 값이 1878로 그대로라 **사이드바 내부는 결과가 전혀 바뀌지 않는다.**

### 2.6 건드릴 곳

- `preview/layout.ts` — 위 상수 정리, `TITLE_EN_SIZE` 제거, `TITLE_KO_SIZE_STEPS` 최소값 변경
- `preview/ScheduleCanvas.tsx` — 제목을 사이드바 열 안으로 이동
- `preview/TitleBar.tsx` — 영문 월 이름 제거
- `preview/Sidebar.tsx` — 자기 높이를 `BODY_HEIGHT`가 아니라 새 상수로
- `model/types.ts`, `model/storage.ts`, `editor/HeaderEditor.tsx` — `showEnglishMonth` 제거

## 3. 다크 테마 선 색

### 3.1 진단

결과 이미지에 실제로 그려지는 선은 `Theme.cellBorder`다. `Theme.borderColor`는 편집 패널의 테마 선택 스와치에만 쓰이고 캔버스에는 쓰이지 않는다.

다크 테마만 유독 대비가 낮다.

| 테마 | 칸 배경 | 선 | 대비 |
|---|---|---|---|
| 핑크 | `#fdf4f6` | `#5b3a42` | 매우 뚜렷 |
| 크림 | `#fffdf8` | `#4a4238` | 매우 뚜렷 |
| 민트 | `#f6fffc` | `#2f5b53` | 매우 뚜렷 |
| **다크** | `#2b2e42` | `#4a4f6b` | **약 1.5:1** |

### 3.2 방향

"색을 더 진하게"로 요청받았지만, 어두운 배경에서 선을 더 어둡게 하면 배경에 묻혀 더 안 보인다. **"더 뚜렷하게"로 읽고 밝은 쪽으로 올린다.**

브라우저에서 후보 네 개를 0.3배(X 타임라인에서 보이는 크기)로 나란히 띄워 확인했고, `#8a90b5`(대비 약 3.5:1)를 골랐다. 다른 테마에서 선이 보이는 느낌과 가장 비슷하다.

```
dark.cellBorder:  #4a4f6b  →  #8a90b5
```

`borderColor`(`#5a5f7d`)는 그대로 둔다. 편집 UI의 밝은 배경 위에 놓이는 스와치 테두리라 밝게 만들면 오히려 안 보인다.

## 4. 배경 이미지 위 달력 투명도

### 4.1 방식

**칸 배경색에만 알파를 준다.** 일정 텍스트와 격자선은 항상 100% 불투명이다.

바깥 요소에 `opacity`를 거는 방법도 있으나 글자까지 함께 흐려져 80% 아래로는 실용성이 없다. 브라우저에서 두 방식을 나란히 확인하고 이쪽으로 정했다. 배경만 투명하게 하면 0%까지 내려도 일정이 또렷하게 읽힌다.

### 4.2 데이터

`ScheduleDoc`에 두 값을 더한다. **슬라이더는 두 개다** — 달력과 사이드바를 따로 조절한다.

```ts
/** 달력 칸 배경 불투명도. 1 = 지금과 같음, 0 = 배경 이미지가 그대로 비침. */
gridOpacity: number
/** 사이드바 박스 배경 불투명도. */
sidebarOpacity: number
```

- 범위 0~1, 기본값 **1**
- 저장은 월별 문서에 담는다. 배경 이미지가 월별이므로 투명도도 월별이어야 짝이 맞는다
- `migrateDoc`은 숫자가 아니거나 범위 밖이면 1로 되돌린다

### 4.3 알파를 입히는 대상

| 요소 | 색 | 적용 슬라이더 |
|---|---|---|
| 날짜 칸 배경 | `entry.cellFill` 또는 `theme.cellBackground` | `gridOpacity` |
| 요일 행 배경 | `theme.dowHeaderBackground` | `gridOpacity` |
| 사이드바 박스 배경 | `theme.cellBackground` | `sidebarOpacity` |
| 사이드바 배지 배경 | `theme.dowHeaderBackground` | `sidebarOpacity` |

**사용자가 고른 칸 강조색(`cellFill`)도 함께 투명해진다.** 강조 칸만 불투명하게 남으면 그 칸만 떠 보인다.

격자선(`cellBorder`), 글자(`bodyText`), 형광펜(`marker`), 날짜 숫자 색은 건드리지 않는다.

### 4.4 구현

`theme/`에 순수 함수 하나를 둔다.

```ts
/** #rrggbb + 알파 → rgba(). 알파가 1이면 원래 문자열을 그대로 돌려준다. */
export function withAlpha(hex: string, alpha: number): string
```

알파 1일 때 원본을 그대로 돌려주는 것이 중요하다. 기본값 상태에서 지금까지 만든 결과물과 문자열 단위로 동일해야 회귀가 없다.

`html-to-image`가 `rgba()`를 처리하는 데는 문제가 없다. 이미 `AutoFitText`의 형광펜이 `linear-gradient`를 쓰고 내보내기에 정상 반영된다.

### 4.5 UI

`BackgroundPicker` 안, 배경 이미지 선택 아래에 슬라이더 두 개를 둔다. 배경 이미지가 없으면 투명도를 조절할 이유가 없으므로 **배경 이미지가 있을 때만 보인다.**

```
배경 이미지  [파일 선택]  [없애기]
달력 투명도    ──────●──  100%
사이드바 투명도 ──────●──  100%
```

## 5. 사이드바 박스 제목 편집

### 5.1 현재

`Sidebar.tsx`에 세 쌍이 하드코딩돼 있다.

```
이번 달의 목표 / GOALS
주요 할 일     / TO-DO LIST
메모          / MEMO
```

### 5.2 데이터

`HeaderConfig`의 세 박스에 각각 두 필드를 더한다.

```ts
goals: { enabled: boolean; label: string; badge: string; lines: string[] }
todo:  { enabled: boolean; label: string; badge: string; items: TodoItem[] }
memo:  { enabled: boolean; label: string; badge: string; text: string }
```

기본값은 지금 하드코딩된 값 그대로다. 상수로 한 곳에 모은다.

```ts
export const BOX_DEFAULTS = {
  goals: { label: '이번 달의 목표', badge: 'GOALS' },
  todo:  { label: '주요 할 일',    badge: 'TO-DO LIST' },
  memo:  { label: '메모',          badge: 'MEMO' },
} as const
```

### 5.3 빈 값 규칙

두 필드가 서로 다르게 동작한다.

| 필드 | 비었을 때 | 이유 |
|---|---|---|
| `label` | **기본값으로 되돌아간다** | 제목이 통째로 사라지면 무슨 박스인지 알 수 없다. `TitleBar.titleText`가 이미 같은 방식이다 |
| `badge` | **배지를 아예 안 그린다** | 요청 그대로. 한글 제목만 남고 오른쪽 회색 배지가 사라진다 |

`SidebarBox`가 `badge`가 빈 문자열이면 `<span>` 자체를 렌더링하지 않는다. 제목 행의 `justify-content: space-between`은 그대로 두면 한글 제목이 왼쪽에 남는다.

### 5.4 UI

`HeaderEditor`의 각 박스 on/off 토글 아래에 입력칸 두 개씩, 총 여섯 개.

```
☑ 이번 달의 목표
   제목   [이번 달의 목표    ]
   배지   [GOALS            ]
   (목표 3줄 입력...)
```

배지 입력칸 placeholder는 `비우면 배지가 사라집니다`로 둬서 규칙을 설명한다.

## 6. 마이그레이션

`storage.ts`의 `migrateDoc`은 알려진 필드만 골라 새 문서를 만드는 방식이라, 이번 변경이 전부 이 함수 한 곳에 모인다.

- `showEnglishMonth` — 읽지 않는다. 예전 문서의 값은 자동으로 버려진다
- `label` / `badge` — 문자열이 아니면 `BOX_DEFAULTS`의 값을 쓴다
- `gridOpacity` / `sidebarOpacity` — 0~1 범위의 숫자가 아니면 1을 쓴다

`DOC_VERSION`은 올리지 않는다. 이 함수가 이미 모든 필드를 개별 검증하므로 버전을 올리면 멀쩡히 되살릴 수 있는 문서를 버리게 된다.

## 7. 범위 밖

- 사이드바 폭 조절 (칸 가로는 지금 그대로 둔다)
- 캔버스 크기·비율 변경
- 다크 이외 테마의 색 조정
- 배경 이미지의 밝기·블러 등 다른 보정
- 사이드바 박스 개수 변경이나 순서 바꾸기
- 배지 글꼴·색 지정

## 8. 작업 순서

2번을 먼저 한다. 레이아웃 상수를 바꾸므로 나중에 하면 4번의 결과를 다시 확인해야 한다. 나머지 셋은 서로 독립적이다.

```
2번(레이아웃) → 3번(테마 값) → 5번(제목 편집) → 4번(투명도)
```

4번을 마지막에 두는 이유: 투명도는 눈으로 확인해야 하는데, 그때 레이아웃과 제목이 이미 최종 모양이어야 판단할 수 있다.
