# 월간 스케줄표 이미지 생성기 — 설계

작성일: 2026-08-08

## 1. 개요

년·월을 고르고 일정을 채워 넣으면 **4000×2250 px 스케줄표 이미지**를 만들어주는 웹 애플리케이션.

- **만드는 사람**: 프로젝트 소유자
- **쓰는 사람**: 지인 스트리머 1명
- **결과물의 용도**: X, 네이버 카페에 올리는 월간 방송 일정 공지 이미지
- **대체 대상**: 현재 포토샵으로 매달 직접 편집하는 작업

백엔드 없이 브라우저 안에서 전부 동작한다. 로그인도 서버 저장도 없다.

## 2. 배경

참고한 것은 두 가지다.

**temis.kr** — 버튜버용 주간 방송 시간표 에디터. 폼에 빈칸을 채우면 실시간 미리보기가 갱신되고 이미지가 나온다. "빈칸을 채우면 결과물이 나온다"는 상호작용 모델을 여기서 가져왔다. 주간 전용이라 월간은 직접 설계했다.

**지인이 현재 쓰는 포토샵 템플릿** (`month.png`로 확인) — 판매용 PSD 템플릿. 레이어 구성이 그대로 공개되어 있어 사실상 렌더링 명세 역할을 한다.

```
타이틀 / 스티커 / 날짜 / 일정 / 형광펜 효과 / 그림 필기
하단 문구 / 테두리 / 패턴 / 스케줄표 배경
```

이 레이어 순서를 웹의 z-축 순서로 그대로 옮긴다. 단 `그림 필기`는 범위에서 제외한다(4절 참고).

> **저작권 참고**: 이 PSD 템플릿은 판매 상품이다. 구매자가 개인 용도로 웹 도구화하는 것은 문제없으나, 동일한 디자인을 공개 서비스로 배포하면 원저작자의 권리와 충돌한다. 본 프로젝트는 개인용이므로 해당하지 않는다. 추후 공개할 경우 디자인을 자체 제작해야 한다.

## 3. 결과물 규격

캔버스 비율은 **16:9** 고정이다. 네 가지 크기로 내보낸다.

| 옵션 | 크기 |
|---|---|
| 원본 | 4000 × 2250 |
| 4K | 3840 × 2160 |
| Full HD | 1920 × 1080 |
| HD | 1280 × 720 |

전부 같은 비율이므로 **4000×2250으로 한 번만 렌더링한 뒤 캔버스에서 축소**해 나머지를 생성한다. 네 번 렌더링하지 않는다.

파일명 형식: `2026-08_스케줄_원본.png`, `2026-08_스케줄_4K.png`, `2026-08_스케줄_FHD.png`, `2026-08_스케줄_HD.png`

## 4. 범위

### 포함

- 년·월 선택 시 달력 격자 자동 생성
- 날짜별 일정 텍스트 입력
- 강조 표시 3종 (칸 배경 채우기 / 텍스트 형광펜 / 날짜 숫자 색상)
- 헤더 구성 요소 on/off (제목, 년월 표기, MEMO, To Do List)
- 하단 문구
- 스티커 자유 배치 (업로드, 드래그 이동, 크기·회전 조절)
- 색상 테마 프리셋
- 배경 이미지 업로드
- 폰트 파일 업로드
- 월별 자동 저장, 지난달 내용 복사
- 4단계 크기 PNG 내보내기

### 제외

명시적으로 만들지 않는 것들이다.

- **그림 필기 / 브러시 도구** — 사용자가 불필요하다고 판단
- **팀 일정 취합** — 백엔드가 필요하므로 프론트엔드 전용 범위 밖
- **로그인 / 계정**
- **주간 모드** — 월간을 먼저 완성한다
- **템플릿 여러 종** — 디자인 1종에 테마 색상만 교체
- **시스템 설치 폰트 자동 인식** — 9.3절에 사유 기재

## 5. 화면 구성

2단 구성이다.

- **넓은 화면**: 좌측 미리보기 / 우측 편집 패널
- **좁은 화면**: 상단 미리보기 / 하단 편집 패널

미리보기는 실제로 4000 px 폭의 DOM이며, `transform: scale(컨테이너폭 / 4000)`으로 축소해 표시한다.

편집 패널 구성:

1. 년·월 선택, 지난달 복사 버튼
2. 헤더 설정 (제목 모드, 년월 표기, MEMO, To Do List)
3. 날짜별 편집 — 격자 순서대로 나열, 각 항목에 텍스트 입력과 강조 선택
4. 하단 문구
5. 스티커 관리
6. 테마 / 폰트 / 배경
7. 내보내기 (크기 선택 + 다운로드)

## 6. 기능 명세

### 6.1 년·월 선택과 달력 생성

년과 월을 고르면 격자를 자동 계산한다.

- **항상 7열 × 6행 = 42칸 고정.** 달마다 행 수가 바뀌지 않는다
- 해당 월의 1일이 무슨 요일인지에 따라 앞을 채우고, 42칸이 찰 때까지 뒤를 채운다
- 앞뒤 달 날짜는 흐린 색으로 표시하며 일정 입력 대상이 아니다
- 주 시작 요일은 **일요일**
- 일요일 날짜 숫자는 기본으로 빨간색

행 수를 고정하는 이유는 어떤 달을 골라도 칸 크기가 동일해야 하기 때문이다. 5주로 끝나는 달과 6주가 필요한 달의 칸 크기가 다르면 매달 결과물의 인상이 달라진다.

### 6.2 날짜 칸

한 칸의 내용은 **날짜 숫자 + 일정 텍스트**뿐이다. 시간·부제 같은 별도 필드는 두지 않는다. 시간을 표기하고 싶으면 일정 텍스트 안에 쓴다.

일정 텍스트는 줄바꿈을 허용하는 자유 텍스트다.

### 6.3 텍스트 자동 맞춤

**칸 크기는 절대 변하지 않는다. 글자가 칸에 맞춰 적응한다.**

- 글자가 넘치면 폰트 크기를 자동으로 줄여 칸에 맞춘다
- 글자가 적으면 칸 중앙에 정렬한다 (가로·세로 모두)
- 하한선은 기본 크기의 50%. 거기까지 줄여도 넘치면 편집 폼에 경고를 표시한다

구현은 `AutoFitText` 컴포넌트로 통일한다. 기본 크기에서 시작해 이진 탐색으로 들어맞는 크기를 찾는다 (8~10회 반복이면 수렴).

**반드시 지켜야 할 것**: 폰트가 로드되기 전에 측정하면 잘못된 크기가 나온다. 화면에서는 정상으로 보이는데 내보낸 이미지에서 글자가 넘치거나 부자연스럽게 작아지는 형태로 드러난다. 따라서 `document.fonts.ready` 이후 반드시 재계산하고, 폰트를 교체할 때마다 전체를 재계산한다.

"주어진 측정값에서 폰트 크기를 고르는" 로직은 순수 함수로 분리해 단위 테스트 대상으로 삼는다. DOM 측정만 컴포넌트에 남긴다.

### 6.4 강조 표시

세 가지가 독립적으로 적용된다.

| 종류 | 설명 |
|---|---|
| 칸 배경 채우기 | 날짜 칸 전체를 지정한 색으로 채움 |
| 텍스트 형광펜 | 일정 텍스트 아래에 형광펜 느낌의 색 밑줄 |
| 날짜 숫자 색상 | 날짜 숫자만 다른 색으로 (공휴일, 특별한 날) |

각각 현재 테마의 강조 팔레트에서 색을 고른다. 선택하지 않으면 적용되지 않는다.

날짜 숫자 색상을 지정하면 6.1의 기본 규칙(일요일 빨강)보다 우선한다. 즉 일요일에 다른 색을 지정하면 그 색이 적용된다.

### 6.5 헤더

구성 요소를 각각 켜고 끌 수 있다.

- **제목** — 두 가지 모드
  - `auto`: 월 이름을 크게 (`MAY`)
  - `custom`: 자유 입력 (`몬몬 5월 스케줄`)
- **년월 표기** — `2026.08` 형식, 제목 위 작은 글씨
- **MEMO** — 줄노트 형태의 자유 입력 영역
- **To Do List** — 체크박스가 있는 항목 목록. 항목 추가·삭제 가능

참고 템플릿의 심플 버전은 넷을 다 쓰고, 꾸민 버전은 커스텀 제목만 쓴다. 둘 다 표현 가능해야 한다.

### 6.6 하단 문구

격자 아래 한 줄 안내 문구. on/off와 자유 입력을 지원한다.

### 6.7 스티커

- PNG 파일 업로드 (투명 배경 권장)
- 미리보기 위에서 드래그로 이동, 핸들로 크기 조절, 회전
- 선택 / 삭제 / 앞뒤 순서 변경
- **좌표는 4000×2250 기준 절대 px로 저장한다.** 화면 픽셀 기준으로 저장하면 다른 크기의 화면에서 편집했을 때 위치가 어긋난다
- 쌓임 순서: 격자 위, 타이틀 아래

### 6.8 테마

한 테마가 정의하는 것: 배경색, 패턴, 테두리, 헤더, 칸 배경, 텍스트 색, 요일 색, 강조 팔레트(6색).

초기 제공: 핑크 / 크림 / 민트 / 다크 4종. 테마 추가는 `theme/themes.ts`에 객체 하나를 추가하는 것으로 끝난다.

배경 이미지·패턴 업로드도 별도로 지원한다.

### 6.9 폰트

- **내장 기본 폰트**: Pretendard를 woff2로 번들
- **사용자 추가**: `.ttf / .otf / .woff / .woff2` 파일 업로드. `FontFace` API로 등록하고 IndexedDB에 보관. 한 번 등록하면 계속 유지된다

**시스템 설치 폰트 자동 인식은 제외한다.** `queryLocalFonts()` API가 존재하지만 크롬 전용이고, 매 접근마다 권한 요청이 필요하며, 그렇게 얻은 폰트를 이미지에 임베딩하는 경로가 불안정하다. 파일 업로드와 결과가 동일하므로 확실한 쪽을 택한다.

### 6.10 저장

월별로 문서를 분리해 보관한다 (`2026-08`, `2026-09` …).

- 년월을 바꾸면 해당 월 문서를 불러오고, 없으면 새로 만든다
- 전환 전에 현재 작업을 자동 저장한다
- **지난달 복사** — 이전 달 문서를 현재 달로 복제한다. 헤더·테마·폰트·하단 문구·스티커는 그대로 가져온다.

  일정 텍스트는 **날짜가 아니라 요일 위치를 기준으로** 옮긴다. 방송 일정은 "매주 화요일"처럼 요일에 묶이는 경우가 대부분이고, "지난달 3일"과 "이번달 3일"은 요일이 다르기 때문이다.

  구체적으로는 이전 달 격자의 `n`번째 칸 내용을 이번 달 격자의 `n`번째 칸으로 옮긴다. 두 격자 모두 42칸 고정이고 같은 요일 열에 정렬되어 있으므로 요일이 자동으로 보존된다. 앞뒤 달 영역에 해당하는 칸의 내용은 버린다.

**저장소를 둘로 나눈다.**

| 대상 | 저장소 | 이유 |
|---|---|---|
| 문서(텍스트) | localStorage | 동기 접근, 크기가 작다 |
| 폰트·이미지 | IndexedDB | localStorage 한도는 약 5MB인데 한글 폰트 하나가 2~10MB다 |

문서에는 에셋의 참조 키만 저장한다.

### 6.11 이미지 내보내기

`html-to-image`로 미리보기 DOM에서 PNG를 추출한다.

```
원본 4000×2250 ─┬─→ 4K       3840×2160
                ├─→ Full HD  1920×1080
                └─→ HD       1280×720
```

축소는 캔버스 `drawImage`로 하며 `imageSmoothingQuality: 'high'`를 지정한다.

**알려진 함정과 대응**

- **첫 렌더링에 폰트가 누락되는 문제** — `document.fonts.ready`를 대기하고, 그래도 불안정한 브라우저를 위해 두 번 렌더링해 두 번째 결과를 사용한다 (`html-to-image`의 알려진 회피책)
- **1~3초 소요** — 진행 표시를 띄우고 버튼을 비활성화한다. 그렇지 않으면 연타로 중복 실행된다
- **실패 시** — 원인을 특정한 메시지를 표시한다

## 7. 데이터 모델

```ts
type ScheduleDoc = {
  version: 1
  year: number                      // 2026
  month: number                     // 1-12

  header: {
    titleMode: 'auto' | 'custom'
    customTitle: string
    showYearMonth: boolean
    memo: { enabled: boolean; text: string }
    todo: { enabled: boolean; items: { text: string; checked: boolean }[] }
  }

  days: Record<string, DayEntry>    // "2026-08-03" → 그날 내용
  footer: { enabled: boolean; text: string }

  themeId: string
  fontId: string
  backgroundAssetId: string | null

  stickers: Sticker[]
}

type DayEntry = {
  text: string                      // 일정. 줄바꿈 허용
  dateColor: string | null          // 날짜 숫자 색
  cellFill: string | null           // 칸 배경 채우기
  marker: string | null             // 텍스트 형광펜 색
}

type Sticker = {
  id: string
  assetId: string                   // IndexedDB의 이미지 참조
  x: number                         // 4000×2250 기준 절대 좌표
  y: number
  width: number
  rotation: number                  // 도 단위
  z: number
}
```

**`days`를 배열이 아니라 날짜 문자열 키의 객체로 둔 이유**: 배열이면 "8월의 3번째 칸"이 몇 번 인덱스인지 매번 계산해야 하는데, 달마다 시작 요일이 달라 계산이 틀리기 쉽다. 날짜 키를 쓰면 그럴 여지가 없다.

**`version` 필드**: 구조가 바뀌었을 때 저장된 데이터를 마이그레이션하기 위한 것이다. 첫 버전부터 넣어두지 않으면 나중에 넣을 수 없다.

## 8. 아키텍처

### 기술 스택

React + TypeScript + Vite. 정적 빌드 결과물만 나오며 서버 코드는 없다.

주요 외부 의존성은 `html-to-image` 하나다.

### 파일 구조

```
src/
  model/
    types.ts        ScheduleDoc, DayEntry, Sticker
    calendar.ts     년·월 → 7×6 격자 (순수 함수)
    storage.ts      localStorage / IndexedDB 저장·불러오기, 마이그레이션
    defaults.ts     빈 문서 생성
  theme/
    themes.ts       색상 프리셋
    fonts.ts        폰트 등록·업로드
  editor/
    EditorPanel.tsx   MonthPicker.tsx   DayEditor.tsx
    ThemePicker.tsx   AssetUploader.tsx FontUploader.tsx
    StickerManager.tsx
  preview/
    ScheduleCanvas.tsx   4000×2250 고정 루트
    CalendarGrid.tsx  DayCell.tsx  AutoFitText.tsx
    Header.tsx  MemoBox.tsx  TodoBox.tsx  Footer.tsx
    StickerLayer.tsx
  export/
    exportImage.ts    PNG 추출 + 4단계 크기
  App.tsx
```

### 핵심 경계: `editor/` 와 `preview/` 의 분리

`preview/` 안의 컴포넌트는 **오직 `ScheduleDoc` 하나만 받아서 그린다.** 입력 처리도 저장 로직도 알지 못한다.

이 경계 덕분에 디자인을 전면 교체해도 `preview/`만 건드리면 되고, 반대로 편집 UI를 개편해도 결과물은 흔들리지 않는다. 향후 수정이 잦을 것이 예상되므로 이 분리를 엄격히 지킨다.

### 렌더링 원칙

**`preview/` 안에서는 모든 치수를 `px`로만 쓴다.** `%`, `rem`, `vw`, 미디어쿼리를 쓰지 않는다.

화면 크기에 반응하는 순간 미리보기와 내보낸 이미지가 어긋난다. 편집 패널은 반응형으로 만들어도 무방하며, 이 제약은 `preview/`에만 적용된다.

CSS 1 px = 결과물 1 px이므로 "보이는 것과 나오는 것이 같다"가 구조적으로 보장된다.

### 레이아웃 초기 수치

4000×2250 기준. 구현 중 조정할 수 있는 출발점이다.

| 항목 | 값 |
|---|---|
| 외곽 여백 | 100 px |
| 헤더 영역 높이 | 420 px |
| 요일 헤더 행 높이 | 90 px |
| 날짜 칸 | 약 542 × 231 px |
| 하단 문구 영역 | 100 px |
| 일정 텍스트 기본 크기 | 44 px (하한 22 px) |

## 9. 에러 처리

| 상황 | 대응 |
|---|---|
| 저장 용량 초과 | 안내 메시지 표시, 사용하지 않는 에셋 정리 유도 |
| 업로드 이미지가 과대 | 자동 리사이즈 (최대 변 2000 px) |
| 폰트 파일 형식 오류 | 등록 실패 메시지, 기존 폰트 유지 |
| 구버전 저장 데이터 | `version`으로 마이그레이션. 실패 시 백업 후 초기화 안내 |
| 년월 전환 | 현재 작업 자동 저장 후 전환 |
| 내보내기 실패 | 원인을 특정한 메시지 표시, 재시도 가능 |

## 10. 테스트 전략

**자동 테스트는 판정이 명확한 곳에만 적용한다.** Vitest를 사용한다.

- `calendar.ts` — 윤년, 항상 42칸인지, 월 시작 요일별 앞뒤 채움, 연말·연초 경계. 여기가 조용히 틀리면 가장 치명적이므로 반드시 테스트한다
- `storage.ts` — 저장·불러오기 왕복, 버전 마이그레이션
- 폰트 크기 선택 로직 — 측정값을 입력받아 크기를 반환하는 순수 함수

**렌더링과 이미지 내보내기는 자동 테스트를 만들지 않는다.** 결과물이 이미지라 자동 판정이 사실상 불가능하고, 스냅샷 테스트를 걸면 디자인을 고칠 때마다 깨져 오히려 방해가 된다.

대신 수동 검증 체크리스트로 대신한다.

- 4개 크기 모두 다운로드되고 크기가 정확한가
- 업로드한 폰트가 결과 이미지에 반영되는가
- 스티커 위치가 미리보기와 결과물에서 일치하는가
- **6주가 필요한 달과 5주로 끝나는 달** 모두 격자가 42칸으로 동일한가
- 긴 텍스트가 자동 축소되고, 짧은 텍스트가 중앙 정렬되는가

## 11. 배포
