# 반복 일정 일괄 삭제 · 칸 추가 문구 — 설계

작성일: 2026-08-09

## 1. 개요

두 가지를 더한다.

1. **반복 일정 일괄 삭제** — 반복 규칙이 칸에 뿌려둔 일정을 버튼 한 번으로 되돌린다.
2. **칸 추가 문구** — 이미 적힌 일정은 그대로 두고, 같은 칸 아래쪽에 별도 문구를 얹는다.

둘은 서로 맞물린다. 삭제가 추가 문구까지 지워버리면 안 되기 때문에 같은 설계에서 다룬다.

## 2. 배경

### 왜 삭제가 필요한가

현재 `RecurringEditor`의 규칙 삭제 버튼은 **규칙 자체만** 지운다. 이미 칸에 박힌 텍스트는 그대로 남아, 되돌리려면 날짜별 일정 패널에서 한 칸씩 손으로 비워야 한다. 규칙을 잘못 적용하면 30칸을 손으로 지우는 상황이 나온다 — 이 도구가 없애려던 바로 그 작업이다.

`applyRecurringRules`는 있는데 그 역함수가 없는 상태다.

### 왜 추가 문구가 필요한가

`덮어씌우기.png`로 확인한 요구는 이렇다.

```
┌──────────────┐
│ 19           │
│              │
│   가나다라    │  ← 반복 규칙이 넣은 일정
│              │
│     12h      │  ← 그 위에 따로 얹은 문구
└──────────────┘
```

방송 제목은 매주 같아서 규칙으로 뿌리지만, 방송 길이(`12h`)는 날마다 다르다. 지금은 이걸 넣으려면 규칙이 넣은 텍스트를 손으로 고쳐야 하고, 그러면 다음에 규칙을 다시 적용할 때 덮어써진다.

## 3. 반복 일정 일괄 삭제

### 3.1 판정 기준

칸의 일정 텍스트가 규칙 텍스트와 **`trim()` 기준 완전 일치**하면 삭제 대상이다.

요일은 보지 않는다. 규칙 요일을 나중에 바꾸면 예전에 뿌려둔 칸이 판정에서 빠져 영영 안 지워지기 때문이다. 텍스트만 보면 "규칙이 넣은 내용은 어디 있든 지운다"가 되어 예측이 단순하다.

여러 규칙이 있으면 그중 **하나라도** 일치하면 대상이다.

부분 일치는 보지 않는다. 손으로 한 글자 고친 칸은 사용자가 의도해서 손댄 칸이므로 남기는 쪽이 안전하다.

### 3.2 지우는 범위

규칙이 **넣었던 것만** 되돌린다.

| 필드 | 삭제 시 | 이유 |
|---|---|---|
| `text` | `''`로 | 규칙이 넣은 것 |
| `cellFill` | `null`로 | 규칙이 넣은 것 |
| `marker` | `null`로 | 규칙이 넣은 것 |
| `dateColor` | **보존** | 규칙이 애초에 안 건드린다 (공휴일 표시 성격) |
| `extra` | **보존** | 규칙이 안 건드린다 (§4) |

결과가 완전히 빈 항목이면 `updateDay`의 기존 규칙대로 `days`에서 키 자체를 지운다.

### 3.3 API

`src/model/recurring.ts`에 추가한다.

```ts
/** 규칙이 넣은 내용과 일치하는 칸을 비운 새 문서를 만든다. */
export function clearRecurringRules(doc: ScheduleDoc, rules: RecurringRule[]): ScheduleDoc

/** 지우면 몇 칸이 바뀌는지. 버튼에 미리 보여주기 위한 것. */
export function countClearTargets(doc: ScheduleDoc, rules: RecurringRule[]): number
```

기존 `plan`/`applyRecurringRules`/`countRuleTargets` 구조를 그대로 따른다. 대상 날짜를 계산하는 내부 함수 하나(`planClear`)를 두고, 삭제와 개수 세기가 그것을 공유한다. 적용 쪽이 이미 이 모양이라 새 패턴을 들이지 않는다.

`usableRules`(요일과 텍스트가 모두 있는 규칙만)를 재사용하되, 삭제는 요일을 안 보므로 텍스트 조건만 쓰는 별도 필터가 필요하다.

### 3.4 UI

`RecurringEditor`의 적용 버튼 줄에 세 번째 버튼을 넣는다.

```
[ 빈 칸만 채우기 (12) ]  [ 전부 덮어쓰기 (18) ]  [ 규칙 지우기 (12) ]
```

- 개수가 버튼에 미리 보이므로 별도 확인 창은 두지 않는다. 0이면 누를 이유가 없고, 12면 무엇이 사라질지 알고 누른다.
- 0칸일 때는 적용 버튼과 같은 방식으로 안내 문구를 띄운다: `지울 칸이 없습니다.`
- 성공 시: `12칸을 비웠습니다.`

## 4. 칸 추가 문구

### 4.1 데이터

`DayEntry`에 필드 하나를 더한다.

```ts
export type DayEntry = {
  text: string
  dateColor: string | null
  cellFill: string | null
  marker: string | null
  /** 일정 아래에 따로 얹는 문구. 없거나 비면 그리지 않는다. */
  extra?: string
}
```

**선택 필드다.** 두 가지 이유가 있다.

첫째, `storage.ts`의 `migrateDoc`은 `days`를 통째로 캐스팅해 넘긴다. 따라서 이 필드가 없는 예전 문서가 그대로 읽히고, **런타임에 `extra`가 없는 항목이 실제로 존재한다.** 필수로 선언하면 타입이 거짓말을 하게 된다. 선택으로 두면 타입이 현실과 맞고 마이그레이션 코드도 필요 없다.

둘째, 필수로 만들면 기존 테스트 6개 파일에 흩어진 `DayEntry` 리터럴 14군데를 전부 고쳐야 한다. 이 기능과 무관한 변경으로 diff가 뒤덮인다.

읽는 쪽은 전부 `entry?.extra ?? ''`로 받는다. `text`와 마찬가지로 `null`이 아니라 빈 문자열을 "없음"으로 본다.

건드릴 곳:

- `model/types.ts` — 필드 추가
- `editor/controls.ts` — `isEmptyEntry`에 `(entry.extra ?? '').trim() === ''` 조건 추가
- `model/recurring.ts` — `plan`이 만드는 `DayEntry`에 `extra: doc.days[cell.date]?.extra` (기존 값 보존)

`model/defaults.ts`의 `createEmptyDayEntry`는 **바꾸지 않는다.** 선택 필드이므로 빈 항목에 넣을 이유가 없고, 넣으면 기존 테스트의 `toEqual` 비교가 깨진다.

`model/copyMonth.ts`도 바꿀 필요가 없다. 항목을 `{ ...entry }`로 복제하므로 `extra`가 자동으로 따라간다.

마지막 항목이 핵심이다. **반복 규칙은 적용이든 삭제든 `extra`를 절대 건드리지 않는다.** 규칙으로 제목을 다시 뿌려도 날짜별로 적어둔 방송 길이는 살아남는다.

### 4.2 그리기

칸의 텍스트 영역을 위아래로 나눈다.

```
CELL_TEXT_HEIGHT = 217   (= CELL_HEIGHT 297 − CELL_PADDING 28 − DATE_NUMBER_BLOCK 52)

extra 없음                    extra 있음
┌──────────────┐             ┌──────────────┐
│ 19           │ 52          │ 19           │ 52
│              │             │   가나다라    │ 139  본문
│   가나다라    │ 217 본문     │              │
│              │             │     12h      │  78  추가 문구
└──────────────┘             └──────────────┘
```

`layout.ts`에 상수를 더한다.

```ts
/** 추가 문구가 쓰는 아래쪽 띠 높이. 기본 크기 한 줄이 들어갈 만큼. */
export const CELL_EXTRA_HEIGHT = 78
export const CELL_EXTRA_BASE_SIZE = 62
export const CELL_EXTRA_MIN_SIZE = 32
```

추가 문구가 본문보다 큰 이유: 이미지에서 `12h`가 `가나다라`보다 눈에 먼저 들어온다. 방송 길이처럼 **짧고 중요한 값**이 들어가는 자리라 위계를 그렇게 잡는다.

`DayCell`에서:

- `extra`가 비어 있으면 본문 `AutoFitText`의 `maxHeight`는 `CELL_TEXT_HEIGHT` 그대로고, 추가 문구 요소는 아예 렌더링하지 않는다. **기존에 만든 일정표는 픽셀 하나 안 바뀐다.**
- `extra`가 있으면 본문은 `CELL_TEXT_HEIGHT − CELL_EXTRA_HEIGHT`, 추가 문구는 `CELL_EXTRA_HEIGHT`를 쓴다.

두 요소 모두 기존 `AutoFitText`를 그대로 쓴다. 각자 자기 영역 안에서 중앙 정렬되고, 길어지면 알아서 줄어들며, 칸 크기는 절대 변하지 않는다. 새 렌더링 코드를 쓰지 않는다.

형광펜(`marker`)은 본문에만 적용한다. 추가 문구에는 `markerColor={null}`을 넘긴다. 강조 수단이 늘어나는 만큼 조합이 복잡해지는데, 지금 요구에 없다.

### 4.3 UI

`DayEditor`의 각 날짜 블록에서 일정 `textarea` 바로 아래에 한 줄 `input`을 둔다.

```
19일 (수)
 일정      ┌────────────────────┐
           │ 가나다라            │
           └────────────────────┘
 추가 문구  ┌────────────────────┐
           │ 12h                │
           └────────────────────┘
 칸 배경    × ■ ■ ■ ■
 형광펜     × ■ ■ ■ ■
 날짜 색    × ■ ■ ■ ■
```

- **라벨은 `추가 문구`다.** `덮어쓰기`가 아니다 — 반복 규칙에 이미 `전부 덮어쓰기` 버튼이 있어 같은 화면에 뜻이 다른 "덮어쓰기"가 둘이 되면 안 된다.
- `textarea`가 아니라 한 줄 `input`이다. 띠 높이가 한 줄 분량이라 줄바꿈을 받을 자리가 없다.
- placeholder: `예) 12h`

`isLikelyOverflowing` 경고는 본문에만 그대로 둔다. 추가 문구는 짧은 값이 들어가는 자리라 넘칠 일이 드물고, 넘쳐도 `AutoFitText`가 줄인다.

## 5. 테스트

기존 테스트 파일 옆에 붙인다. 모두 순수 함수 단위 테스트다.

**`model/recurring.test.ts`에 추가**

- 규칙 텍스트와 일치하는 칸이 비워진다
- 한 글자라도 다른 칸은 남는다
- 앞뒤 공백만 다른 칸은 지워진다 (`trim` 비교)
- 규칙 요일이 아닌 날에 있어도 텍스트가 맞으면 지워진다
- `dateColor`는 보존된다
- `extra`는 보존된다
- 지운 뒤 완전히 빈 항목은 `days`에서 키가 사라진다
- `countClearTargets`가 실제 변경 칸 수와 일치한다
- 규칙이 없거나 대상이 0칸이면 문서가 그대로(동일 참조) 반환된다
- `applyRecurringRules`가 기존 `extra`를 덮어쓰지 않는다 (두 모드 모두)

**`preview/DayCell.test.ts`에 추가**

- `extra`가 비면 본문 영역 높이가 `CELL_TEXT_HEIGHT`다
- `extra`가 있으면 본문 영역이 `CELL_TEXT_HEIGHT − CELL_EXTRA_HEIGHT`다

높이 계산을 `DayCell`에서 작은 순수 함수(`splitCellText(extra: string)`)로 빼내 테스트한다. 기존 `dateNumberColor`가 이미 그 방식이다.

**`editor/controls.test.ts`에 추가**

- `extra`만 있는 항목은 빈 항목이 아니다 (`updateDay`가 키를 지우지 않는다)
- `extra`를 지우면 다른 필드가 다 비어 있을 때 키가 사라진다
- `extra`가 아예 없는 예전 모양의 항목도 빈 항목 판정이 예외 없이 동작한다

## 6. 범위 밖

- 추가 문구의 색·형광펜 지정
- 추가 문구의 위치 선택 (항상 칸 아래쪽 고정)
- 반복 규칙으로 추가 문구를 일괄 입력하는 기능
- 삭제 되돌리기(undo)
- 캔버스 위 자유 배치 텍스트 (스티커처럼 칸 경계를 무시하는 텍스트)

마지막 항목은 별도 기능이다. 필요해지면 그때 따로 설계한다.
