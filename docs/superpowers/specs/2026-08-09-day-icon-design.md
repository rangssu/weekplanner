# 날짜 칸 아이콘 — 설계

작성일: 2026-08-09

## 1. 개요

편집 패널에서 아이콘을 **클릭 한 번**으로 날짜 칸에 찍는 기능. 도장을 찍듯 쓴다.

지금은 같은 일을 하려면 스티커를 캔버스 위로 끌어다 놓아야 하는데, 스티커는 좌표에 묶여 있어 매달 다시 배치해야 한다. 이 아이콘은 **날짜에 묶여** 있어서 「지난달 내용 가져오기」가 요일에 맞춰 함께 옮겨준다.

## 2. 결정된 사항

브라우저에 목업을 띄워 사용자가 직접 고른 값이다.

| 항목 | 결정 |
|---|---|
| 위치 | 일정 텍스트 자리(칸 본문 영역) 중앙 |
| 크기 | **166px 정사각** (캔버스 4000px 기준), 고정 |
| 색 | 원본 그대로, 흐리게 하지 않음 |
| 칸당 개수 | 하나 |
| 목록 | 9종을 앱에 내장 |

166px은 추가 문구가 있을 때의 본문 영역 높이(`CELL_TEXT_HEIGHT 244 − CELL_EXTRA_HEIGHT 78`)와 같다. 즉 **추가 문구가 있어도 넘치지 않는 최대 크기**다.

추가 문구가 없으면 본문이 244px이므로 아이콘 위아래 여백만 늘어난다. 크기는 그대로 둔다 — 칸마다 크기가 달라지면 한 달치를 훑을 때 들쭉날쭉해 보인다.

## 3. 아이콘 목록

`src/assets/dayIcons/`에 9개를 넣는다. 원본 파일명(`1.png`…)은 뜻을 담고 있지 않으므로 **뜻이 담긴 id**를 따로 둔다. 저장된 문서가 참조하는 값이라 한 번 정하면 바꾸지 않는다.

| id | 그림 | 라벨 |
|---|---|---|
| `star` | 노란 별 | 별 |
| `game` | 분홍 게임패드 | 게임 |
| `movie` | 파란 클래퍼보드 | 영화 |
| `together` | 초록 사람들 | 합방 |
| `note` | 보라 메모+펜 | 메모 |
| `pen` | 주황 연필 | 그림 |
| `talk` | 진회색 말풍선 | 저챗 |
| `rest-ko` | 「휴방」 도장 | 휴방 |
| `rest-hanja` | 「休」 도장 | 휴 |

**용량**: 9개 합계 약 1.05MB(500×500 PNG). 지금 PWA 프리캐시가 612KB이므로 약 1.7MB가 된다. `vite.config.ts`의 한도가 6MB라 문제없다. 화면에 그려지는 크기가 166px이라 500px 원본은 3배 과하지만, 다시 인코딩하면 손실이 생기고 빌드 단계가 늘어나므로 원본을 그대로 쓴다.

## 4. 데이터

`DayEntry`에 필드 하나를 더한다.

```ts
/** 칸에 찍은 아이콘 id. 없거나 모르는 id면 그리지 않는다. */
icon?: string
```

`extra`와 같은 이유로 **선택 필드**다 — `migrateDoc`이 `days`를 통째로 캐스팅하므로 이 필드가 없는 예전 문서가 실제로 존재한다.

### 4.1 반드시 함께 고쳐야 하는 곳

이 필드를 더하면서 **놓치면 데이터가 조용히 사라지는 지점**이 셋 있다. 앞선 작업에서 같은 함정을 이미 한 번 밟았으므로 명시한다.

| 위치 | 해야 할 일 | 안 하면 |
|---|---|---|
| `model/defaults.ts`의 `isBlankDayEntry` | `icon` 조건 추가 | 아이콘만 있는 칸을 `updateDay`가 빈 칸으로 보고 **키를 지운다** |
| `model/recurring.ts`의 `plan` | `icon` 물려받기 | 반복 규칙을 다시 적용하면 아이콘이 사라진다 |
| `model/recurring.ts`의 `planClear` | `icon` 보존 | 「규칙 지우기」가 아이콘까지 지운다 |

`copyMonth.ts`는 `{ ...entry }`로 복제하므로 손댈 필요가 없다.

### 4.2 모르는 id

저장된 문서에 등록되지 않은 id가 들어 있으면 **아무것도 그리지 않는다.** 깨진 이미지 아이콘이 결과물에 박히는 것보다 낫다. 조회는 등록표에서 `find`로 하고 못 찾으면 `undefined`를 반환한다.

## 5. 그리기

`DayCell`의 본문 영역에 아이콘을 **글자 뒤**로 깐다.

```
┌──────────────┐
│ 12           │  날짜 52px
│    ╭────╮    │
│    │ 🎮 │    │  본문 166px — 아이콘 166×166 중앙
│    ╰────╯    │
│     12h      │  추가 문구 78px
└──────────────┘
```

- 아이콘이 없으면 요소를 **아예 렌더링하지 않는다.** 기존 결과물이 픽셀 단위로 같아야 한다.
- 글자와 아이콘이 둘 다 있으면 글자가 위에 온다. 사용자는 아이콘을 쓸 때 글자를 안 쓸 예정이지만, 둘 다 있어도 읽을 수 있어야 한다.
- 아이콘은 `pointer-events: none`, 본문 영역 밖으로 넘치지 않게 `overflow: hidden`.

`layout.ts`에 상수를 둔다.

```ts
/**
 * 칸에 찍는 아이콘 한 변.
 *
 * 추가 문구가 있을 때의 본문 높이(CELL_TEXT_HEIGHT − CELL_EXTRA_HEIGHT)와 같다.
 * 파생식으로 쓰지 않고 값을 직접 적는다 — 추가 문구 띠 높이를 조정할 때
 * 아이콘 크기까지 딸려 움직이면 눈치채기 어렵다. 대신 둘의 관계는 테스트로 지킨다.
 */
export const CELL_ICON_SIZE = 166
```

## 6. 편집 UI

`DayEditor`의 각 날짜 블록, `추가 문구` 입력칸 **다음**에 아이콘 줄을 둔다.

```
19일 (수)
 일정      [ 가나다라           ]
 추가 문구  [ 12h               ]
 아이콘     [×] ⭐ 🎮 🎬 👥 📝 ✏️ 💬 휴방 休
 칸 배경    × ■ ■ ■ ■
```

- 맨 앞 `×`가 「없음」이다. 기존 강조 스와치 줄(`SwatchRow`)이 이미 같은 꼴이라 그 관습을 따른다.
- 고른 아이콘은 테두리로 표시한다(`aria-pressed`).
- 각 버튼에 `aria-label`로 라벨을 준다.

## 7. 내보내기

`html-to-image`가 `<img>`를 data URL로 인라인해야 결과 PNG에 아이콘이 들어간다. 아이콘은 같은 출처에서 오는 번들 자산이라 CORS 문제는 없다.

**이 부분은 반드시 실제로 내보내 확인한다.** 이 프로젝트에서 미리보기와 내보낸 이미지가 어긋나는 것이 가장 비싼 실패다. 배경 이미지가 이미 data URL로 잘 들어가고 있으므로 전망은 좋지만, `<img>` 태그는 경로가 다르다.

## 8. 범위 밖

- 아이콘 직접 올리기 (9종 내장만)
- 칸당 여러 개
- 날짜별 크기·위치 조절
- 반복 규칙으로 아이콘 일괄 찍기
- 아이콘 색 바꾸기

## 9. 작업 순서

```
1. 자산·등록표  →  2. 데이터 필드(+세 지점)  →  3. 그리기  →  4. 편집 UI  →  5. 내보내기 확인·점검 문서
```

2번을 3번보다 먼저 하는 이유: 필드가 없으면 그릴 게 없고, 4.1의 세 지점을 나중에 하면 그 사이에 만든 문서가 손상된다.
