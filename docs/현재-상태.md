# 현재 상태 (2026-08-11 기준)

월간 스케줄표 이미지 생성기. **4000×2250 PNG**를 브라우저 안에서만 만든다. 백엔드가 없다.

| 항목 | 값 |
|---|---|
| 배포 | https://dapper-unicorn-879a97.netlify.app/ (`main` 푸시 시 Netlify 자동 빌드) |
| 소스 | `src/` 아래 TypeScript·TSX 약 8,700줄 |
| 테스트 | **388개 / 33개 파일**, 전부 통과 (`npm test`) |
| 스택 | React 18 · Vite 7 · vitest · html-to-image · vite-plugin-pwa |
| 저장 | localStorage(문서·규칙) + IndexedDB(폰트·이미지 파일) |
| 상태 | 실사용 가능. 핵심 기능은 다 붙었고, 남은 것은 3장 참고 |

이 문서는 **지금 무엇이 있는지**만 적는다. 왜 그렇게 만들었는지는 `2026-08-10-작업-기록.md`, 앞으로 무엇을 확인해야 하는지는 `manual-checklist.md`에 있다.

## 1. 기능 목록

### 1.1 달력

| 기능 | 내용 |
|---|---|
| 년·월 선택 | 고르면 격자를 자동 생성. **항상 7열 × 6행 = 42칸** 고정 |
| 앞뒤 달 날짜 | 흐린 색으로 함께 그린다 |
| 일정 텍스트 | 날짜별 자유 입력, 줄바꿈 허용 |
| 글자 자동 축소 | 칸을 넘치면 52px → 최소 26px까지 단계적으로 줄인다 (`AutoFitText`) |
| 넘침 경고 | 최소 크기로도 안 들어가면 편집 패널에 경고를 띄운다 |
| 추가 문구 | 일정 아래에 얹는 짧은 문구(`12h` 같은 것). 있을 때만 띠를 잡는다 |
| 날짜 칸 아이콘 | 9종 중 하나를 칸당 하나, 166px 정사각으로 찍는다 |
| 강조 3종 | 칸 배경 채우기 / 텍스트 형광펜 / 날짜 숫자 색. 각각 테마 색 6종에서 고른다 |

**아이콘 9종** — `star`(별) · `game`(게임) · `movie`(영화) · `together`(합방) · `note`(메모) · `pen`(그림) · `talk`(저챗) · `rest-ko`(휴방) · `rest-hanja`(휴).

파일명이 아니라 뜻이 담긴 id로 저장하므로 나중에 그림을 갈아끼워도 저장된 문서가 그대로 동작한다. 모르는 id는 아무것도 안 그린다.

고르는 UI는 **3×3 그리드**다. 한 번에 한 날짜만 편집하므로 접지 않는다.

### 1.2 헤더와 사이드바

캔버스 왼쪽 900px 열에 제목과 박스 3개가 세로로 쌓인다. 달력은 그 오른쪽에서 캔버스 세로를 전부 쓴다.

| 요소 | 내용 |
|---|---|
| 제목 | `auto`(「8월」) 또는 `custom`(자유 입력). 길이에 따라 130 / 112 / 80px |
| 이번 달의 목표 | 밑줄 3줄. on/off |
| 주요 할 일 | 체크박스 목록. on/off |
| 메모 | 자유 텍스트. on/off |

박스 3개는 **제목과 배지를 각각 편집**할 수 있다. 둘이 일부러 다르게 동작한다 — 제목을 비우면 기본값(「이번 달의 목표」)으로 되돌아가고, 배지를 비우면 **배지를 아예 안 그린다.**

제목이 900px 열에 갇혀 있어 **11자를 넘으면 말줄임표로 잘린다.**

### 1.3 반복 일정

「매주 화·목 21시 방송」 같은 고정 요일 스케줄을 규칙으로 저장한다. 이 도구가 템플릿 파일을 이기는 지점이다.

- 규칙은 **월별 문서가 아니라 전역**으로 저장된다 (`weekplanner:rules`). 새 달을 열어도 규칙이 살아 있다
- 적용 방식 2가지 — 「빈 칸만 채우기」 / 「덮어쓰기」
- 여러 규칙이 같은 요일을 다루면 **목록 위쪽이 이긴다**
- 「규칙 지우기」로 뿌려둔 일정을 되돌린다. 텍스트가 **완전 일치**하는 칸만 지우므로 손으로 고친 칸은 살아남는다
- 적용·삭제 버튼에 **대상 개수가 미리 뜬다** (`규칙 지우기 (12)`)

규칙이 건드리는 필드는 `text` · `cellFill` · `marker` 셋뿐이다. `dateColor`(공휴일 빨간 숫자) · `extra`(추가 문구) · `icon`은 **날짜에 묶인 값**이라 규칙이 절대 덮지 않는다.

### 1.4 꾸미기

| 기능 | 내용 |
|---|---|
| 테마 5종 | 파스텔 **핑크·크림·민트** / 무채색 **화이트·다크** (고르는 칸이 3열이라 두 줄로 떨어진다) |
| 폰트 | 번들 2종(카페24 동동 / 시스템 기본) + **파일 업로드**(woff2·woff·ttf·otf) |
| 배경 이미지 | 업로드해서 캔버스 전체에 깐다 |
| 투명도 | 배경이 있을 때만 보이는 슬라이더 2개 — **달력용 / 사이드바용** |
| 스티커 | 이미지를 자유 배치. 드래그 · 크기 · 회전 · 순서 |
| 글자색 | 5영역(제목·목표·할 일·메모·달력) 각각 자동/직접. 자동은 배경 이미지 밝기로 고른다 |

**투명도는 칸 배경색에만 알파를 준다.** 격자선·일정 글자·형광펜·날짜 숫자는 항상 100% 불투명이다. 바깥 요소에 `opacity`를 걸면 글자까지 흐려져 80% 아래로는 못 쓴다.

배경을 없애면 투명도도 함께 1로 되돌아간다(고아 값 방지). 배경을 **교체**할 때는 사용자가 고른 투명도를 유지한다.

**배경 이미지가 없으면 자동은 계산하지 않고 테마 기본색을 쓴다.** 계산하면
저장된 모든 문서의 모습이 바뀐다.

밝기는 **불투명도를 반영한 실효 밝기**로 판정한다 — 글자는 배경 이미지 위에
바로 얹히지 않고 사이에 알파가 들어간 테마 배경색이 있다. 불투명도가 1이면
배경 이미지는 아예 안 보인다.

영역마다 배경 이미지의 **그 자리만** 잰다. 왼쪽이 어둡고 오른쪽이 밝은
사진에서도 사이드바와 달력이 따로 판정된다.

### 1.5 날짜 편집

미리보기 달력 칸을 클릭해 그 날짜를 편집한다. 31일치 목록은 없다.

- PC는 **칸 옆 팝오버**, 폰은 **바텀시트**. 폼은 한 벌이고 껍데기만 둘이다
- 아무것도 안 고른 상태로 시작한다. 앞뒤 달 칸은 눌러도 반응하지 않는다
- `‹ ›`는 **그 달 안에서만** 움직인다. 달 전환은 `MonthPicker`의 일이다
- 해제는 `✕` · `Esc` · 바깥 클릭 · 같은 칸 재클릭

편집 패널은 **탭 3개**다 — 달력(년·월, 반복 일정) / 꾸미기(테마, 글자색,
배경, 투명도, 폰트, 스티커) / 사이드바(제목, 상자 3개). 이미지 저장은 탭 밖 맨 위,
저장 공간은 맨 아래 한 줄이다.

### 1.6 저장과 내보내기

- **월별 자동 저장** — 마지막 입력에서 400ms 조용하면 저장. 월을 옮길 때는 즉시 저장
- **지난달 내용 가져오기** — 날짜가 아니라 **격자 위치**로 옮기므로 요일이 보존된다. 아이콘도 함께 따라간다
- **용량 초과 감지** — localStorage 쿼터가 차면 편집 패널에 알린다
- **PNG 4단계** — 원본(4000×2250) / 4K(3840×2160) / Full HD / HD. 전부 16:9
- 파일명은 `2026-08_스케줄_원본.png` 형식

## 2. 구조

### 2.1 코드 계층

```
src/
  model/      도메인 타입, 달력 계산, 저장소, 반복 규칙. React를 모른다
  preview/    ScheduleDoc 하나만 받아 그리는 표시 계층 = 내보내기 대상
  editor/     입력 UI
  export/     PNG 추출과 축소
  state/      문서 상태와 자동 저장 훅
  theme/      색상 테마, 폰트, 아이콘 등록표
  assets/     번들 폰트·아이콘 원본 파일
```

**규칙 두 개가 이 프로젝트를 지탱한다.**

1. **`preview/` 안에서는 `px`만 쓴다.** `%`·`rem`·`vw`·미디어쿼리 금지. 화면 크기에 반응하는 순간 미리보기와 내보낸 이미지가 어긋난다. 화면에 맞춘 축소는 `editor/PreviewStage.tsx`가 담당한다.
2. **`preview/` 컴포넌트는 `ScheduleDoc`만 받는다.** 저장 함수나 setter를 넘기지 않는다. 스티커 드래그 조작을 `editor/StickerDragLayer.tsx`로 따로 뺀 것도 이 때문이다.

`preview/`의 DOM이 곧 `html-to-image`가 직렬화하는 트리다. 즉 **화면에 보이는 것이 결과물 그 자체**다.

### 2.2 데이터 모델

```ts
ScheduleDoc            // 한 달치. 저장 단위이자 preview/의 유일한 입력
  version: 1
  year, month
  header               // 제목 모드 + 박스 3개(enabled·label·badge·내용)
  days                 // { "2026-08-03": DayEntry }, 그 달 날짜만
  themeId, fontId
  backgroundAssetId    // IndexedDB 참조. null이면 테마 기본 배경
  gridOpacity          // 0~1, 기본 1
  sidebarOpacity
  stickers[]
  textColors?          // 5영역 각각 자동/직접. 없으면 전부 자동

DayEntry               // 하루 칸. 날짜 숫자 외에 담기는 전부
  text                 // 일정 텍스트
  dateColor            // 날짜 숫자 색. null = 요일 기본 규칙
  cellFill             // 칸 배경. null = 안 채움
  marker               // 형광펜. null = 안 그림
  extra?               // 추가 문구 (선택 필드)
  icon?                // 아이콘 id (선택 필드)

RecurringRule          // 전역 저장. 문서에 안 들어간다
  id, weekdays[], text, cellFill, marker
```

`extra`와 `icon`이 **선택 필드**인 것은 의도다. `migrateDoc`이 `days`를 통째로 캐스팅해 넘기므로 이 필드가 없는 예전 문서가 그대로 읽힌다. 필수로 선언하면 타입이 런타임 값과 어긋난다.

### 2.3 저장 위치

| 곳 | 키 | 내용 |
|---|---|---|
| localStorage | `weekplanner:doc:2026-08` | 월별 문서 (JSON) |
| localStorage | `weekplanner:rules` | 반복 규칙 (전역) |
| IndexedDB | `weekplanner` / `assets` | 업로드한 폰트·배경·스티커 파일 |

IndexedDB에는 Blob을 **ArrayBuffer로 풀어서** 넣는다. 브라우저 편차가 있고 테스트 환경(fake-indexeddb)이 Blob을 빈 객체로 만들어 버려 왕복 검증이 불가능해지기 때문이다.

`migrateDoc`은 **알려진 필드만 골라** 새 문서를 만든다. `...raw`로 퍼뜨리면 없앤 기능의 흔적이 계속 딸려 들어온다. 예전 `priorities` → 현재 `memo` 같은 개명도 여기서 흡수한다.

### 2.4 캔버스 기하 (4000×2250)

```
┌──────────────────────────────────────────────┐  바깥 여백 90
│ ┌────────┐ ┌───────────────────────────────┐ │
│ │ 제목    │ │                               │ │  제목 900×160
│ │ 160px  │ │        달력 2880×2070          │ │
│ ├────────┤ │   요일행 90 + 6행 × 329px      │ │  달력은 세로 전체
│ │사이드바 │ │        칸 411 × 329           │ │
│ │900×1878│ │                               │ │
│ └────────┘ └───────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

수치는 전부 `src/preview/layout.ts`에서 파생된다. **어디에도 하드코딩하지 않는다.**

칸 안쪽 텍스트 영역은 추가 문구 유무로 갈린다 — 없으면 본문이 244px 전부, 있으면 본문 166px + 추가 문구 띠 78px. 아이콘 한 변 166px은 **추가 문구가 있어도 안 넘치는 최대 크기**다.

## 3. 알려진 제약과 남은 일

### 3.1 의도적으로 남겨둔 것

| 항목 | 상태 |
|---|---|
| **실행 취소가 앱 전체에 없다** | 삭제 버튼이 개수를 미리 보여주는 것이 유일한 안전장치 |
| 「휴방」만 찍은 날이 「빈 칸만 채우기」에 덮어써짐 | 사용자에게 알리고 보류. 고친다면 `hasContent`에 `icon`을 더하는 것이 맞는 지점 |
| 규칙 텍스트를 고치면 예전 도장이 고아가 됨 | 「규칙 지우기」가 텍스트 완전 일치로 판정하기 때문. 안내 문구가 조건을 설명하고 있어 치명적이진 않다 |
| 제목 11자 초과 시 말줄임 | 제목을 사이드바 열로 옮긴 대가. 「길어지면 그때 말하겠다」로 정리됨 |
| `RecurringRule.marker` | 편집 UI가 없어 항상 비어 있다 |
| 아이콘 프리캐시 1.7MB | 500px 원본을 166px로 쓰므로 3배 과하다. 한도(6MB)에 여유가 있어 재인코딩은 안 했다 |
| 폰에 클릭 단서가 없다 | 호버가 없기 때문. PC를 기준으로 설계한 결과 |
| 폰에서 칸이 39×31px | 손가락으로 정확히 눌러야 한다 |
| 좌표 계산이 두 벌 | 클릭은 CSS 그리드, 팝오버는 `cellScreenRect`. 테스트로 묶어 둔다 |
| 밑줄·체크박스 테두리는 안 바뀐다 | `theme.cellBorder`다. 선까지 따라가게 하면 「글자색」이 아니라 「테마 자동 반전」이 되어 범위가 훨씬 커진다 |
| 배지·요일 헤더·상자 힌트 제외 | 앞의 둘은 자기 배경색 위에 있고, 힌트는 비어 있을 때만 보이는 안내다 |
| 칸 배경 채우기가 반영 안 됨 | 영역 평균이라 `cellFill`을 칠한 칸 하나하나는 계산에 안 들어간다 |

### 3.2 아직 안 만든 것

- 그림 필기 / 브러시 도구
- 주간 모드
- 팀 일정 취합, 로그인 (백엔드가 필요하므로 범위 밖)
- 시스템 설치 폰트 자동 인식 (사유는 설계 문서 6.9절)

### 3.3 다음에 확인할 것

1. **저장해둔 지난 달들** — 저장 형식이 최근 네 번 바뀌었다(추가 문구 → 투명도 → 박스 제목 → 아이콘). `migrateDoc`이 모든 세대를 무손실 통과하는 것은 확인했지만 실제 데이터로 볼 필요가 있다
2. **아이콘 찍고 PNG 내보내기** — 픽셀 검증은 했지만 실제 사용 환경에서 한 번 더

### 3.4 칸 클릭 편집에서 미뤄둔 것

브랜치 리뷰에서 나왔지만 이번 범위 밖으로 둔 것들이다. 전부 동작을 막지 않는다.

| 항목 | 내용 |
|---|---|
| 탭의 ARIA가 절반이다 | `role="tablist"`·`role="tab"`·`aria-selected`는 있는데 `role="tabpanel"`·`aria-controls`가 없고 좌우 화살표 키 이동도 없다. 스크린리더가 탭이라 읽고도 연결된 패널을 못 찾는다 |
| 팝오버·시트에 포커스 관리가 없다 | `role="dialog"`인데 열릴 때 안으로 포커스를 옮기지 않고 닫을 때 되돌리지도 않는다. DOM 순서상 Tab으로 도달은 된다 |
| 바텀시트는 바깥을 눌러도 안 닫힌다 | 팝오버와 동작이 갈린다. 백드롭도 없다 |
| 정리 버튼의 안전성 설명이 사라졌다 | 「저장 공간」을 한 줄로 줄이면서 "어떤 달에서도 쓰지 않는 파일만 지웁니다"가 빠졌다. 파일을 지우는 버튼이라 `title` 정도로는 되살릴 값이 있다 |
| 팝오버 화살표가 clamp를 못 따라간다 | 팝오버가 화면 안으로 밀리면 화살표가 칸을 정확히 가리키지 못한다. 모서리 고정 방식의 한계이고 코드 주석에 적혀 있다 |
| `EditorPanel`에 전용 테스트가 없다 | 섹션 12개가 각 탭에 다 배치됐는지는 사람 눈으로만 확인했다. 탭별 섹션 존재를 보는 테스트 3개면 회귀가 막힌다 |

## 4. 검증

### 4.1 자동

```
npm test        # 388개
npx tsc -b      # 타입 검사
```

렌더링과 이미지 내보내기는 자동 테스트를 만들지 않았다. 결과물이 이미지라 자동 판정이 어렵고, 스냅샷 테스트는 디자인을 고칠 때마다 깨져 방해가 된다.

대신 **계산 가능한 것은 전부 테스트가 잡는다** — 달력 격자, 텍스트 분할, 넘침 판정, 반복 규칙 적용·삭제, 저장 마이그레이션, 색 알파, 아이콘 등록표, 이미지 축소.

### 4.2 수동

`docs/manual-checklist.md`에 항목이 있다. 미리보기 DOM이 곧 내보내기 대상이라 자동 테스트만으로는 부족하다.

> **픽셀 검사 시 주의**: `offsetWidth === 4000`인 div가 셋 있다. 실제 캔버스는 **계산된 `backgroundColor`가 투명하지 않은** 것이다. 래퍼를 잡으면 전부 0이 나와 내보내기가 깨진 것처럼 보인다.

## 5. 고칠 때 알아야 할 함정

전부 **화면에서는 멀쩡해 보이는데 결과물이나 특정 상황에서만 어긋나는** 종류다.

| 함정 | 내용 |
|---|---|
| 폰트 등록 | `FontFace` API를 쓰면 화면엔 나오지만 **내보낸 이미지에서 빠진다.** `<style>`에 data URL `@font-face`로 등록해야 한다 (`html-to-image`가 `document.styleSheets`만 훑음) |
| CSS 단축 속성 | `background`와 `backgroundImage`를 함께 쓰면 단축 속성이 갱신될 때 이미지가 통째로 날아간다. `backgroundColor`를 쓴다 |
| `cacheBust` | `exportImage.ts`에서 반드시 꺼 둔다. 켜면 서비스 워커 프리캐시가 매칭되지 않아 **오프라인에서 이미지가 조용히 빠진 PNG**가 나온다 |
| `border-box` 테두리 | 캔버스(10px)와 격자(5px) 모두 계산에서 빼야 한다. 빼먹으면 `overflow: hidden` 때문에 화면상 티가 안 난다. 고친 뒤엔 **사방 여백 실측** |
| 정수 vs 소수 | `scrollWidth`는 정수인데 칸 폭은 `3840/7`처럼 소수다. 그대로 비교하면 모든 글자가 최소 크기까지 줄어든다 (`AutoFitText`가 `Math.floor`를 쓰는 이유) |
| 글자 크기 기준 | 4000px 이미지는 X 타임라인에서 ~1200px로 줄어 보인다. 배율 0.3이라 **캔버스에서 「충분히 커 보이는」 크기가 실제로는 작다** |
| 브라우저 자동화 | 탭이 `hidden`이면 Chrome이 `requestAnimationFrame`·`ResizeObserver`를 멈춘다. 반응형 확인은 보이는 창에서 사람이 해야 한다 |
| 캔버스의 CSS 전환 | 전환 중에 캡처하면 중간 색이 PNG에 박힌다. `exportImage.ts`가 캡처 전후로 `transition`을 껐다 켠다 |
