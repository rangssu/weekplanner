## 1. 만든 기능

### 1.1 반복 일정 일괄 삭제

반복 규칙이 칸에 뿌려둔 일정을 버튼 하나로 되돌린다. 예전에는 규칙 삭제 버튼이 **규칙 객체만** 지우고 칸에 박힌 텍스트는 남겨서, 되돌리려면 30칸을 손으로 비워야 했다 — 이 도구가 없애려던 바로 그 작업이다.

`applyRecurringRules`는 있는데 역함수가 없던 상태였다. `clearRecurringRules`를 짝으로 붙였다.

**판정 기준**: 칸의 일정 텍스트가 규칙 텍스트와 `trim()` 기준 **완전 일치**할 때만 지운다. 한 글자라도 손으로 고친 칸은 살아남는다.

**요일을 보지 않는다.** 규칙 요일을 나중에 바꾸면 예전에 뿌려둔 칸이 판정에서 빠져 영영 안 지워지기 때문이다.

**되돌리는 범위**: `text` → `''`, `cellFill` → `null`, `marker` → `null`. `dateColor`(공휴일 빨간 숫자)와 `extra`(추가 문구), `icon`은 규칙이 애초에 안 건드리므로 보존한다.

버튼에 대상 개수가 미리 뜬다(`규칙 지우기 (12)`). 확인 창은 두지 않았다 — 개수가 보이는 것이 안전장치다.

### 1.2 칸 추가 문구

날짜마다 일정 아래에 짧은 문구를 따로 얹는다. 방송 제목은 매주 같아 규칙으로 뿌리지만 방송 길이(`12h`)는 날마다 달라서, 규칙 텍스트를 손으로 고치면 다음 적용 때 덮어써지던 문제를 푼다.

칸 텍스트 영역을 본문/추가 문구로 나눈다. **추가 문구가 비면 본문이 전체를 쓰므로 예전 결과물은 픽셀 하나 안 바뀐다.**

**반복 규칙은 이 필드를 절대 건드리지 않는다.** 규칙으로 제목을 다시 뿌려도 날짜별 방송 길이는 살아남는다.

### 1.3 달력 세로 확대

"칸 너비 증가"로 요청받았지만 참고 이미지를 캔버스 4000px 기준으로 환산해 재보니 **가로는 그대로, 세로가 커진 것**이었다.

원인은 제목 줄이었다. 제목이 캔버스 전체 폭을 가로질러 달력이 그 아래 1878px만 썼다. 제목을 **사이드바 열 위로** 옮겨 달력이 캔버스 세로 전체(2070px)를 쓰게 했다.

```
이전                              이후
┌─────────────────────────┐      ┌────────┬────────────────┐
│ 8월              AUGUST │      │ 8월    │                │
├────────┬────────────────┤      ├────────┤   달력          │
│사이드바 │  달력           │      │사이드바 │  (세로 전체)    │
└────────┴────────────────┘      └────────┴────────────────┘
```

- `CELL_HEIGHT` 297 → **329px** (+11%), `CELL_WIDTH`는 410.57 그대로
- `BODY_HEIGHT`가 사이드바와 달력 두 뜻을 갖게 되어 `SIDEBAR_HEIGHT`(1878)와 `GRID_AREA_HEIGHT`(2070)로 쪼갰다
- 사이드바 높이는 1878로 같아 **사이드바 내부는 결과가 전혀 안 바뀐다**

**대가**: 제목이 900px 열에 갇혀 **11자를 넘으면 말줄임표로 잘린다.** 최소 글자 크기를 104 → 80으로 낮춰도 그렇다. 사용자에게 알렸고 "길게 쓰게 되면 그때 말하겠다"로 정리됐다.

**「AUGUST」 영문 월 이름 표기는 기능째로 제거**했다. 900px 열에 「8월」과 나란히 둘 자리가 없다.

### 1.4 다크 테마 격자선

결과 이미지에 실제로 그려지는 선은 `Theme.cellBorder`다(`borderColor`는 편집 패널 스와치 전용). 다크만 유독 대비가 낮았다 — `#4a4f6b` on `#2b2e42`는 약 1.5:1.

두 번에 걸쳐 조정했다. 요청은 "색을 더 진하게"였지만 **어두운 배경에서 선을 더 어둡게 하면 배경에 묻혀 더 안 보인다.** "더 뚜렷하게"로 읽고 밝은 쪽으로 올렸다.

1차: `#4a4f6b` → `#8a90b5` — 여전히 흐리다는 피드백
2차: `#8a90b5` → **`#c6cbdd`**, 그리고 **구분선 두께 3 → 5px**

두께가 결정적이었다. 얇은 선은 축소될 때(4000px 이미지가 X 타임라인에서 ~1200px) 뭉개져서 색만으로는 한계가 있다.

**바깥 테두리는 3px 그대로 뒀다.** 이것까지 굵히면 격자 안쪽 높이가 줄어 마지막 주가 4px 잘린다. 구분선은 칸 안쪽으로 들어가므로(`box-sizing: border-box`) 두께를 바꿔도 기하가 안 흔들린다.

`Theme.cellBorderWidth`를 새로 뒀고, `CELL_TEXT_*`는 **가장 두꺼운 경우(5px)를 기준으로** 계산한다. 테마마다 달라지면 `splitCellText`와 `isLikelyOverflowing`이 전부 테마를 알아야 해서다.

### 1.5 배경 이미지 위 투명도 조절

배경 일러스트가 달력을 통해 비쳐 보이게 한다.

**칸 배경색에만 알파를 준다.** 격자선·일정 글자·형광펜·날짜 숫자는 항상 100% 불투명이다. 바깥 요소에 `opacity`를 걸면 글자까지 흐려져 80% 아래로는 못 쓴다 — 브라우저에 두 방식을 나란히 띄워 확인하고 정했다.

**달력용·사이드바용 슬라이더 2개**를 따로 뒀다. 배경 이미지가 있을 때만 보인다.

알파를 씌우는 대상은 정확히 넷: 날짜 칸 배경, 요일 행 배경, 사이드바 박스 배경, 사이드바 배지 배경. **사용자가 고른 강조색(`cellFill`)도 함께 투명해진다** — 안 그러면 그 칸만 불투명하게 떠 보인다.

`withAlpha(hex, alpha)`가 **알파 1이면 원본 문자열을 그대로 돌려준다.** 기본값이 1이므로 이래야 기능을 넣기 전 결과물과 문자열 단위로 같아진다.

### 1.6 사이드바 박스 제목·배지 편집

「이번 달의 목표 / GOALS」 같은 세 쌍이 하드코딩돼 있던 것을 편집 가능하게 했다.

두 필드가 **일부러 다르게 동작**한다:

| 필드 | 비었을 때 | 이유 |
|---|---|---|
| 제목 | 기본값으로 되돌아감 | 제목이 사라지면 무슨 박스인지 알 수 없다 |
| 배지 | **배지를 아예 안 그림** | 요청 그대로. 한글 제목만 남는다 |

`BOX_DEFAULTS`가 기본값의 단일 출처다. `mergeHeader`는 `typeof v === 'string'`으로 검사해 **빈 문자열이 저장·복원을 견딘다** — 배지를 일부러 비운 설정이 새로고침 후에도 유지되려면 그래야 한다.

### 1.7 테마 고르는 칸 3+2 배치

`flex-wrap`이라 패널 폭에 따라 4+1로 갈리면서 성격이 다른 테마가 한 줄에 섞였다. 열을 3으로 고정하고 `THEMES` 순서를 파스텔 먼저로 바꿔 **핑크·크림·민트 / 화이트·다크**로 떨어지게 했다.

### 1.8 날짜 칸 아이콘

아이콘 9종을 클릭 한 번으로 날짜 칸에 찍는다. 도장처럼 쓴다.

스티커와 다른 점: 스티커는 캔버스 좌표에 묶여 매달 다시 배치해야 하지만, **이 아이콘은 날짜에 묶여** 있어 「지난달 내용 가져오기」가 요일에 맞춰 함께 옮겨준다.

| id | 그림 | 라벨 |
|---|---|---|
| `star` | 노란 별 | 별 |
| `game` | 분홍 게임패드 | 게임 |
| `movie` | 파란 클래퍼보드 | 영화 |
| `together` | 초록 사람들 | 합방 |
| `note` | 보라 메모+펜 | 메모 |
| `pen` | 주황 연필 | 그림 |
| `talk` | 진회색 말풍선 | 저챗 |
| `rest-ko` | 「휴방」 도장 | 휴방 |
| `rest-hanja` | 「休」 도장 | 휴 |

- 일정 텍스트 자리 중앙, **166px 정사각 고정**, 원본 색, 칸당 하나
- 166px은 추가 문구가 있을 때의 본문 높이와 같다 = **추가 문구가 있어도 안 넘치는 최대 크기**
- 글자 뒤에 깔린다. 보통 아이콘을 쓸 땐 글자를 안 쓰지만, 둘 다 있어도 글자가 읽힌다
- 파일명(`1.png`…)이 아니라 **뜻이 담긴 id**를 쓴다 — 나중에 그림을 교체해도 저장된 문서가 그대로 동작한다
- 모르는 id는 아무것도 안 그린다. 깨진 이미지가 결과 PNG에 박히는 것보다 낫다

**고르는 UI는 두 번 만들었다.** 처음엔 한 줄에 버튼 10개를 늘어놓았는데 패널 폭(약 300px)을 넘겨 두 줄로 접히고 28px이라 그림 구분이 어려웠다. 이 줄이 **날짜마다 하나씩 31벌 쌓인다**는 게 문제였다.

후보 4개를 동작하는 목업으로 만들어 고른 결과: **접이식 3×3**. 평소엔 고른 아이콘 하나만 한 줄로 보이고, 누르면 46px 그리드가 펼쳐지고, 고르면 다시 접힌다. 한 번에 한 날짜만 열린다. **접힌 상태가 예전 두 줄짜리보다 세로 공간을 약 45% 덜 쓴다.**

## 2. 고친 버그

### 2.1 글자가 잘려도 경고가 안 뜨던 문제 · Important

`isLikelyOverflowing`이 「글자가 너무 많아 칸에서 잘릴 수 있습니다」 경고를 띄울 때 본문 영역을 **여전히 전체 높이로 계산**했다. 추가 문구가 있으면 본문은 그보다 좁다.

즉 **실제로 잘리는데 경고가 안 떴다.** 원래 주석이 "경고가 조금 이르게 뜨는 쪽이 안전하다"고 밝힌 설계 원칙의 정반대 방향으로 깨진 것이다.

`splitCellText`를 `layout.ts`로 옮기고 `isLikelyOverflowing(text, extra)`가 실제 본문 높이로 계산하게 고쳤다.

### 2.2 빈 항목 판정 중복 · Important

`recurring.ts`의 `isBlank`와 `controls.ts`의 `isEmptyEntry`가 같은 규칙을 손으로 두 번 쓴 상태였다. `DayEntry`에 필드가 하나 늘 때 한쪽만 고치면 **내용이 남은 칸의 키가 삭제되고 400ms 뒤 자동 저장된다.** 이 앱에는 실행 취소가 없다.

계획에 "`model/`이 `editor/`를 import하면 계층이 뒤집힌다"고 정당화를 써뒀었는데 **그 근거가 사실이 아니었다.** 아무도 그 방향을 제안한 적 없고, 공통 술어의 자연스러운 위치는 `model/defaults.ts`이며 `controls.ts`는 이미 거기서 import하고 있었다. `isBlankDayEntry` 하나로 합쳤다.

### 2.3 배경을 없애면 투명도가 고아가 되던 문제 · Important

「배경 없애기」를 누르면 슬라이더 UI는 사라지는데 `gridOpacity: 0.4` 같은 값은 문서에 남아 계속 적용됐다. **달력이 흐린 채로 고정되고 되돌릴 UI가 화면에 없다.** 자동 저장되고, 그 상태로 내보낸 PNG가 게시된다.

`handleRemove`가 `backgroundAssetId`를 지우는 **같은 `setDoc` 안에서** 투명도도 1로 되돌리게 고쳤다. 중간 렌더나 자동 저장이 끼어들 틈이 없다.

배경 **교체**는 투명도를 유지한다 — 그건 사용자가 고른 값이다.

### 2.4 테마를 바꾸면 배경 이미지가 사라지던 문제 · Important (직접 신고)

`ScheduleCanvas`가 CSS **단축 속성** `background`로 테마 색을 주면서 **개별 속성** `backgroundImage`도 함께 썼다.

테마를 바꾸면 React가 값이 바뀐 `background`만 다시 쓴다. 그런데 CSS 단축 속성은 `background-image`를 포함한 모든 배경 속성을 초기화한다. `backgroundImage`는 값이 그대로라 React가 다시 안 써준다 → **그림이 통째로 날아간다.**

배경을 없앴다 다시 넣으면 돌아온 것도 이 때문이다. 그때는 `backgroundImage` 값이 바뀌니까.

`backgroundColor`로 고쳤다. 개별 속성끼리는 서로를 초기화하지 않는다.

`src/preview/`의 다른 `background:` 사용처(칸·요일행·사이드바 박스)는 전부 색만 쓰고 배경 이미지 개별 속성이 없어 같은 함정에 안 걸린다.

### 2.5 PWA 오프라인 내보내기에서 이미지가 빠지던 문제 · Important (이 세션 이전부터)

`exportImage.ts`의 `cacheBust: true`가 자산 URL에 `?타임스탬프`를 붙인다. 서비스 워커의 프리캐시 조회는 이 쿼리를 무시하지 않으므로(workbox 기본값은 `utm_`·`fbclid`만 무시) **프리캐시가 매칭되지 않고 네트워크로 나간다.**

오프라인이면 fetch가 실패하고 `html-to-image`는 빈 문자열로 대체한 뒤 **그것을 모듈 캐시에 넣는다.** 그래서 아이콘이 전부 빠진 PNG가 나오고, 다시 내보내도 계속 빠진다 — 전체 새로고침 전까지.

Vite가 이미 파일명에 내용 해시를 붙이므로 `cacheBust`는 **얻는 것 없이 이 손해만** 있었다. `false`로 껐다.

이 브랜치 이전에도 번들 폰트가 같은 경로로 오프라인에서 빠지고 있었다. 아이콘 9개가 들어오면서 영향 범위가 1개 → 10개로 넓어져 드러났다.

### 2.6 아이콘 열림 상태가 31일 전체를 다시 그리던 문제 · Important

접이식 그리드의 열림 상태를 `DayEditor`에 두면서, 아이콘 하나를 눌러도 **31개 날짜 블록이 전부 다시 렌더링**됐다. 이전 방식은 상태가 아예 없어 이런 재렌더가 없었다.

`DayBlock`을 `React.memo`로 떼어내고 `patch`를 `useCallback`으로 안정화했다. 계측으로 확인: 마운트 시 31개 전부, 이후 토글마다 **1~2개만** 다시 그린다.

## 3. 남겨둔 것

### 3.1 「휴방」 아이콘만 찍은 날이 「빈 칸만 채우기」에 덮어써짐

`hasContent`가 `dateColor`·`extra`·`icon`을 일부러 판정에서 뺀다. 「빈 칸만 채우기」는 "일정 글자가 없는 칸"을 뜻하도록 설계됐고 `extra`와 일관된 처리다.

결과적으로 「휴방」 도장만 찍어둔 날에 방송 일정이 덮어써진다. 사용자에게 알렸고 **"일단 인지만"으로 보류**했다.

고치기로 한다면 `plan()`이 아니라 **`hasContent`에 `icon`을 추가**하는 것이 맞는 지점이다.

### 3.2 규칙 텍스트를 고치면 예전 도장이 고아가 됨

「규칙 지우기」는 텍스트 완전 일치로 판정한다. 규칙 요일을 바꾸는 경우는 대비했지만 **텍스트를 바꾸는 경우**는 아니다.

「발로란트 21:00」을 4개 화요일에 뿌린 뒤 규칙 텍스트를 22:00으로 바꾸면, 「지울 칸이 없습니다」가 뜨고 예전 4칸은 지울 방법이 없다. 안내 문구가 조건을 설명하고 있어 치명적이진 않다.

### 3.3 그 밖

- **실행 취소가 앱 전체에 없다.** 삭제 버튼이 개수를 미리 보여주는 것이 유일한 안전장치다.
- `RecurringRule.marker`는 편집 UI가 없어 항상 비어 있다.
- 아이콘 9개가 프리캐시를 약 0.63MB → 1.7MB로 키웠다. 한도(6MB)에는 여유가 있다. 500px 원본을 166px로 쓰므로 3배 과하지만, 재인코딩은 손실과 빌드 단계를 늘려 하지 않았다.
- `DayEditor.test.tsx`의 `setDoc` 스텁이 no-op이라, 아이콘을 고를 때 `doc.days`에 제대로 쓰이는지는 테스트하지 않는다. 열고 닫는 UI 상태만 검증한다.

## 4. 검증 방식

이 프로젝트는 **미리보기 DOM이 곧 내보내기 대상**이라(`html-to-image`가 그 트리를 직렬화) 자동 테스트만으로는 부족하다. 다음을 브라우저에서 직접 확인했다.

**레이아웃** — 실제 DOM을 재서: 캔버스 4000×2250, 격자 x=1030 y=90 2880×2070(세로 전체), 제목 x=90 y=90 900×160(왼쪽 열 안), 칸 42개 각 329px. 16자 제목은 80px로 줄고 말줄임 처리되며 **격자를 밀지 않는다.**

**투명도** — 달력 50%/사이드바 40%에서 칸 `rgba(43,46,66,0.5)`, 요일 행 `rgba(58,62,88,0.5)`, 사이드바 `rgba(43,46,66,0.4)`, 격자선 `rgb(138,144,181)`(알파 없음), 날짜 숫자 `rgb(138,182,255)`(알파 없음).

**내보내기 PNG를 픽셀 단위로** — 배경 그림 위 칸 안쪽이 `rgb(92,62,128)`로 혼합되고 격자선은 `rgb(138,144,181)` 그대로. 혼합 계산과 정확히 일치했다(`#2b2e42`를 50%로 `#8b4fc0` 위에 얹으면 `(91, 62.5, 129)`).

**아이콘 내보내기** — 12일 칸 중앙 `rgba(212,138,137,255)`(분홍 게임패드), 아이콘 없는 칸과 여백은 순백. `html-to-image`가 번들 `<img>`를 제대로 인라인한다.

**반복 삭제 시나리오** — 규칙 적용 → 한 칸에 추가 문구 → 다른 칸 손수 수정 → `규칙 지우기 (3)`(수정한 칸 제외) → 3칸 비워짐, 추가 문구 살아남음, 완전히 빈 칸은 키 삭제, 두 번째 클릭에 「지울 칸이 없습니다」.

> **픽셀 검사 시 주의**: `offsetWidth === 4000`인 div가 셋 있다. 실제 캔버스는 **계산된 `backgroundColor`가 투명하지 않은** 것이다. 래퍼를 잡으면 전부 0이 나와 내보내기가 깨진 것처럼 보인다.

## 5. 테스트 관련 메모

**공허한 테스트 두 건을 잡아 고쳤다.** 「아이콘을 지우면 항목이 사라진다」류의 테스트가 **수정 없이도 통과**하고 있었다 — 아이콘만 있는 항목은 옛 코드에서 애초에 저장조차 안 되므로 두 번째 호출이 없는 키에 no-op이 되고 단언이 그대로 성립했다.

고친 형태: 아이콘 + 다른 내용으로 시작 → 다른 것을 지우고 **항목이 살아있는지 단언**(이 줄이 핵심) → 아이콘을 지우고 키가 사라지는지 단언.

**증명 방식**: 수정을 일부러 되돌려 해당 테스트만 실패하는 것을 확인했다. 통과만 보여주는 건 이 경우 의미가 없다.

**jsdom에 없던 `document.fonts`를 `src/test/setup.ts`에 채웠다.** 없으면 `AutoFitText`를 쓰는 컴포넌트를 아예 렌더링할 수 없어 미리보기 쪽 컴포넌트 테스트가 불가능하다. 이 위에 배경 버그 회귀 테스트(`ScheduleCanvas.test.ts`)와 아이콘 렌더링 테스트(`DayCell.test.tsx`)가 올라가 있다.
