# 수동 검증 체크리스트

렌더링과 이미지 내보내기는 결과물이 이미지라 자동 판정이 어렵다. 스냅샷 테스트를
걸면 디자인을 고칠 때마다 깨져 오히려 방해가 되므로 이 목록으로 대신한다.

**이 파일에는 사람이 직접 봐야 하는 것만 남긴다.** 자동 테스트가 이미 보장하는
것은 [2장](#2-자동-테스트가-보장하는-것)에 체크박스 없이 적어 두었다 — 손으로
다시 확인하지 않기 위한 목록이다. 정말 사람이 봐야 하는 항목이 그 사이에 묻히면
아무도 이 파일을 끝까지 읽지 않는다.

`npm run dev` 후 `http://localhost:5173/`에서 확인한다.
**디자인이나 레이아웃 상수를 고친 뒤에는 1장을 전부 다시 확인한다.**

---

## 1. 사람이 반드시 봐야 하는 것

jsdom에는 레이아웃이 없어 `scrollWidth`·`offsetWidth`가 전부 0이고, 이미지 디코딩과
폰트 로딩도 일어나지 않는다. 아래는 그래서 자동으로 판정할 수 없는 것들이다.

### 1.1 글자 자동 축소

`AutoFitText`가 실제 DOM을 재서 크기를 정한다. 계산 로직은 `fitText.test.ts`가
검증하지만, **재는 값 자체는 브라우저에서만 나온다.**

- [ ] 긴 일정 텍스트가 자동으로 작아져 칸 안에 들어간다
- [ ] **짧은 텍스트는 기본 크기 그대로 나온다** — 짧은 글까지 작아지면 측정 반올림
      함정에 걸린 것이다. `scrollWidth`는 정수인데 칸 폭은 `2874/7`처럼 소수라,
      상자를 내림하지 않으면 어떤 크기도 "안 맞음"이 된다 (`AutoFitText`의 `boxWidth`)
- [ ] 짧은 텍스트가 칸 중앙에 정렬된다
- [ ] **폰트를 바꾼 뒤에도 텍스트가 칸을 넘지 않는다** — `document.fonts` 로딩 이벤트로
      재측정이 도는지 보는 것이다. jsdom에는 그 API가 없어 스텁으로 때워 두었다
- [ ] 아주 긴 텍스트를 넣어도 칸 크기와 격자 위치가 변하지 않는다
- [ ] 긴 추가 문구를 넣어도 칸 크기와 격자 위치가 변하지 않고 글자만 작아진다

### 1.2 레이아웃 실측

- [ ] **캔버스 사방 여백이 균등하다** — 개발자 도구로 재보면 확실하다. 어긋나면
      `box-sizing: border-box` 요소의 테두리를 계산에서 빠뜨린 것이다
- [ ] **달력이 캔버스 안쪽 세로를 전부 쓴다** — 요일 행 위와 마지막 주 아래에 빈 틈이 없다
- [ ] 제목이 사이드바 열 안에 있고, 사이드바 폭을 넘지 않는다
- [ ] 긴 제목을 넣어도 말줄임표로 잘릴 뿐 사이드바를 밀어내지 않는다
- [ ] 「주요 할 일」 상자가 사이드바 밖으로 넘치지 않는다
- [ ] 추가 문구가 칸 아래쪽에 **본문보다 큰 글씨로** 그려진다
- [ ] 아이콘과 일정 글자가 둘 다 있으면 글자가 위에 온다
- [ ] 추가 문구가 있는 칸에서도 아이콘이 잘리지 않는다

> **픽셀 검사 시 주의**: `offsetWidth === 4000`인 div가 셋 있다. 실제 캔버스는
> **계산된 `backgroundColor`가 투명하지 않은** 것이다. 래퍼를 잡으면 전부 0이 나와
> 내보내기가 깨진 것처럼 보인다.

### 1.3 달력 칸 클릭 편집

- [ ] **창 폭을 여러 번 바꿔가며, 눈에 보이는 칸과 실제로 눌리는 칸이 같은지**
      확인한다. 수치는 `cellGeometry.test.ts`가 맞물림을 보장하지만 브라우저
      서브픽셀 반올림은 계산으로 확정할 수 없다
- [ ] **팝오버 입력칸에서 한글이 정상적으로 입력되는지 — IME 후보창 위치 포함.**
      좌표 계산을 두 벌 감수한 **유일한 이유**가 이것이다. 틀어지면 설계 결정을
      다시 봐야 한다 (`cellGeometry.ts` 주석 참고)
- [ ] 토요일 열과 마지막 주 칸에서 팝오버가 뒤집혀 뜬다
- [ ] 창을 좁혔을 때 팝오버가 화면 안으로 밀려 들어온다
- [ ] **작은 노트북(1366×768)에서 3~4주차 칸을 눌러 팝오버 전체가 화면 안에 들어온다**
      — 컨테이너가 낮으면 시트 안에서 스크롤된다
- [ ] **같은 칸을 다시 눌러 선택이 풀린다** — 넓은 화면과 좁은 화면 양쪽에서
- [ ] `✕` · `Esc` · 바깥 클릭으로도 풀린다
- [ ] 앞뒤 달 칸은 눌러도 아무 일이 없다
- [ ] 달을 바꾸면 선택이 풀린다
- [ ] 스티커가 놓인 칸에서 **스티커가 여전히 끌린다** — 오버레이가 위를 덮으면 안 된다
- [ ] 폰 폭에서 시트가 올라오고, 닫으면 선택이 풀린다
- [ ] 폰에서 폼이 시트 안에서 스크롤된다

### 1.4 영역별 글자색

밝기 계산은 `luminance.test.ts`·`textColors.test.ts`가 검증하지만, **실제 이미지
디코딩과 합성 결과는 브라우저에서만 볼 수 있다.**

- [ ] 어두운 사진과 밝은 사진을 각각 올려 5영역이 알맞게 바뀐다
- [ ] **불투명도를 1로 올리면 글자색이 테마 기준으로 돌아온다** — 이 기능의 핵심이다.
      배경 이미지가 안 보이는데 이미지 밝기로 정하면 틀린다
- [ ] 왼쪽이 어둡고 오른쪽이 밝은 사진에서 사이드바와 달력이 따로 판정된다
- [ ] **배경 이미지가 없는 저장된 지난 달을 열어 모습이 그대로다** — 한 픽셀도
      달라지면 안 된다
- [ ] **투명한 부분이 있는 PNG**를 올려도 판정이 뒤집히지 않는다 (긴 변 2000 이하로
      올려야 리사이즈를 안 거친다)
- [ ] 손상된 파일을 올리면 테마 기본색으로 떨어진다
- [ ] 한 영역을 직접 색으로 바꾼 뒤 배경을 갈아도 그 영역만 유지된다
- [ ] 다크 테마에 밝은 사진을 깔면 글자가 어두워진다 — 테마 극값이 실제로 쓰이는
      유일한 조합이다
- [ ] 사이드바 불투명도를 0으로 내리고 어두운 사진을 깔았을 때 **배지와 안내 문구도
      함께 밝아진다** (메모 상자를 비운 채로 보면 안내 문구만 보인다)

### 1.5 이미지 내보내기 (가장 중요)

`preview/`의 DOM이 곧 결과물이다. 이 절이 이 프로젝트에서 가장 자주 깨진 곳이다.

- [ ] 네 가지 크기가 모두 받아진다
- [ ] 파일 크기가 정확히 4000×2250 / 3840×2160 / 1920×1080 / 1280×720이다
- [ ] 파일명이 `2026-08_스케줄_원본.png` 형태다
- [ ] **업로드한 폰트가 결과 이미지에 반영되어 있다** (확인법은 3장)
- [ ] 배경 이미지가 결과에 들어 있다
- [ ] **PNG에 아이콘이 들어 있다** — 빠지면 `html-to-image`가 이미지를 인라인하지 못한 것이다
- [ ] 스티커 위치·크기·회전이 미리보기와 일치한다
- [ ] 자동 축소된 텍스트가 화면과 같은 크기로 나온다
- [ ] 투명도를 내린 상태가 결과 이미지에도 반영된다
- [ ] 추가 문구가 결과 이미지에 미리보기와 같은 위치·크기로 나온다
- [ ] **날짜를 고른 상태로 내보내 파란 선택 테두리가 없다** — 오버레이가 `canvasRef`
      바깥에 있어 구조상 불가능하지만 계약이므로 한 번은 본다
- [ ] 배경을 바꾸자마자 곧바로 내보내도 결과가 올바르다
- [ ] 만드는 동안 버튼이 잠기고 "만드는 중…"이 보인다
- [ ] **오프라인에서 내보내도 아이콘이 빠지지 않는다** — 빠지면 `cacheBust`가 켜진 것이다
- [ ] **아이패드에서 원본 크기를 내보내도 탭이 죽지 않는다.** 이 앱이 아이패드에서
      쓰이기 때문에 있는 항목이다. 캔버스 하나가 RGBA로 36MB고 `renderCanvasPng`가
      `toPng`를 두 번 부르는데, 원본은 크기가 같아 `downscalePng`를 건너뛰도록
      해 두었다(`needsDownscale`). 되돌리면 iOS Safari가 탭을 통째로 날린다.
      **배경 이미지와 스티커를 여러 개 얹은 무거운 문서로 확인한다** — 빈 문서로는
      한계에 안 닿는다
- [ ] 원본을 건너뛰게 한 뒤에도 **4K·FHD·HD가 여전히 정확한 크기로 나온다** —
      축소 경로는 그대로 살아 있어야 한다

### 1.6 파일 업로드와 시각 확인

- [ ] 폰트 파일(.ttf/.woff2)을 추가하면 즉시 적용된다
- [ ] `.png` 같은 잘못된 파일을 고르면 안내가 뜬다
- [ ] 배경 이미지를 올리고 없앨 수 있다
- [ ] **배경 이미지를 올린 뒤 테마를 바꿔도 그림이 그대로 남는다** — 사라지면 캔버스가
      단축 속성 `background`로 되돌아간 것이다
- [ ] 스티커를 끌어 옮기면 따라오고, **창 폭을 바꿔도 정확히 따라온다**
- [ ] 스티커 크기·회전·앞뒤 순서가 반영된다
- [ ] **다크 테마에서 격자선이 뚜렷하게 보인다** — 결과 이미지를 1200px로 줄여도
      칸 경계가 구분된다
- [ ] 테마 5종이 모두 적용되고 편집 패널의 강조 스와치 색도 따라 바뀐다
- [ ] 아이콘을 고르면 그 날짜 칸 가운데에 원본 색 그대로 나온다
- [ ] 칸 배경 채우기·형광펜·날짜 색이 눈으로 확인된다
- [ ] 달력 투명도를 내리면 칸으로 배경이 비치고, **일정 글자와 격자선은 또렷하게 남는다**
- [ ] 배경 이미지가 없으면 투명도 슬라이더가 보이지 않는다

### 1.7 저장 왕복

localStorage·IndexedDB 왕복은 `storage.test.ts`·`assets.test.ts`가 로직을 검증하지만,
**실제 브라우저 저장소에서의 동작은 직접 봐야 한다.**

- [ ] 새로고침해도 입력한 내용·추가 문구·아이콘이 남아 있다
- [ ] **아이콘만 있는 칸이 새로고침 후에도 남아 있다** — 사라지면 빈 항목 판정에서
      아이콘을 빠뜨린 것이다
- [ ] 비운 배지가 새로고침 후에도 그대로 없다
- [ ] 새로고침해도 마지막 편집 탭이 유지된다
- [ ] 월을 바꿨다 돌아오면 내용이 그대로다
- [ ] **저장 형식이 여러 번 바뀌었다.** 아주 오래된 달을 열어 무손실로 읽히는지 본다

### 1.8 편집 패널

- [ ] 「사이드바」 탭에 제목과 상자 3개가 모두 있다
- [ ] 「꾸미기」 탭에 「글자색」이 있고 영역 다섯 개가 보인다
- [ ] 직접 입력 제목에 한글을 넣어도 잘리지 않는다
- [ ] 「주요 할 일」 항목을 체크하면 미리보기 체크박스에 `V`가 나온다
- [ ] 세 상자의 제목·배지를 바꾸면 미리보기에 반영된다

### 1.9 이미지·폰트 보관함

목록과 삭제 판정은 `AssetLibrary.test.tsx`·`assets.test.ts`가 검증한다. **여기 있는
것은 지운 결과가 화면과 결과물에 실제로 반영되는지**다 — 캐시가 남아 있어도 자동
테스트는 통과하는데 사용자 눈에는 삭제가 실패한 것으로 보이는 자리다.

- [ ] **쓰고 있는 배경을 지우면 미리보기에서 곧바로 사라진다.** 남아 있으면
      `forgetAssetUrl`을 안 부른 것이다 (`useAssetUrl`이 모듈 캐시를 쓴다)
- [ ] **그 상태로 내보낸 PNG에도 배경이 없다.** 화면에서 사라져도 결과물에 남을 수
      있어 따로 본다. 이쪽이 더 위험하다
- [ ] **쓰고 있는 폰트를 지우면 폰트 선택 목록에서 빠지고, 미리보기가 기본 폰트로
      돌아간다.** 목록에 남으면 `onAssetsChange`로 폰트를 다시 읽지 않은 것이다
- [ ] **방금 올려서 아직 어느 달에도 적용하지 않은 폰트가 「사용 안 함」에 뜬다.**
      예전에는 이런 파일이 확인 없이 지워졌다. 목록에 보이는 것 자체가 안전장치다
- [ ] 사용 중인 파일을 지울 때 확인 창에 **영향받는 달이 실제 달로 적혀 있다**
      (두 달에서 쓰는 파일로 확인한다)
- [ ] 확인을 취소하면 아무 일도 안 일어난다
- [ ] 「미사용 전체 지우기」 뒤에도 사용 중인 파일과 그것을 쓰는 달의 모습이 그대로다
- [ ] 접힌 줄의 개수가 실제 보관 개수와 맞고, **펼치기 전에는 파일 이름이 안 보인다**
      — 펼칠 때만 읽는 것이 아이패드 메모리 때문에 있는 설계다
- [ ] **배경이나 폰트를 올리면 접힌 줄의 개수가 그 자리에서 바뀐다.** 올리는 곳은
      보관함이 아니라 각자의 섹션이라, 저장소가 알리지 않으면 "0개"인 채로 남아
      방금 올린 파일이 없는 것처럼 보인다 (`onAssetsChanged`)
- [ ] **폰트를 올린 직후 곧바로 보관함에서 그 폰트를 지워 본다.** 자동 저장이
      400ms 디바운스라 그 순간에는 「사용 안 함」으로 보이는데, 눌러도 지워지지
      않고 「지금 쓰고 있어 지우지 않았습니다」가 뜨면서 「사용 중」으로 옮겨
      가야 한다. 지워지면 **지금 쓰는 파일이 확인도 없이 사라진 것**이다 —
      한 번 이렇게 나갔던 자리다
- [ ] 크기가 KB로 표시되고, 큰 폰트 파일이 실제로 크게 보인다

### 1.10 새 버전 알림

**실제 배포가 있어야 확인할 수 있다.** 서비스 워커가 새 자산을 받아야 하므로
`npm run build && npm run preview`로 두 번 빌드하거나 배포본으로 본다.

- [ ] 새 버전을 올린 뒤 열어 둔 앱에 **배너가 뜬다**
- [ ] **누르기 전에는 새로고침되지 않는다** — 일정을 입력하는 도중에 확인한다.
      예전에는 이 지점에서 화면이 말없이 초기화됐다

## 3. 폰트 임베딩을 확실히 확인하는 법

눈으로는 판단하기 어렵다. 개발자 도구 콘솔에서 폰트를 바꿔가며 결과 픽셀이
달라지는지 보면 확실하다.

```js
const mod = await import('/src/export/exportImage.ts')
const canvas = [...document.querySelectorAll('#root div')]
  .find(d => d.offsetWidth === 4000).firstElementChild
const hash = async () => {
  const url = await mod.renderCanvasPng(canvas)
  const img = new Image(); img.src = url; await img.decode()
  const c = document.createElement('canvas'); c.width = 1000; c.height = 563
  const ctx = c.getContext('2d'); ctx.drawImage(img, 0, 0, 1000, 563)
  const d = ctx.getImageData(0, 0, 1000, 563).data
  let h = 0
  for (let i = 0; i < d.length; i += 4) h = (h * 31 + d[i] + d[i+1]*3 + d[i+2]*7) >>> 0
  return h
}
await hash()   // 폰트를 바꾼 뒤 다시 실행해 값이 달라지는지 본다
```

값이 **같으면** 폰트가 임베딩되지 않고 폴백된 것이다.
